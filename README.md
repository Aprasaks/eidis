# EIDIS / JARVIS

개인용 JARVIS의 초기 프로토타입입니다. **아직 완성된 AI 비서가 아닙니다.**

- `app.py` / `jarvis/`: Python localhost 서버, 규칙 기반 명령, 명시적 SQLite 기억
- `web/`: 입자 호출 → 은은한 작업 공간 전환, API 기반 현황, 4개 사전 제작 디자인 시안의 미리보기/적용/되돌리기
- `jarvis/design.py`: 자연어에 맞춘 로컬 디자인 토큰 조합, 선택적으로 실행하는 외부 AI 구조화 설계 어댑터
- `macos/`: SwiftUI 네이티브 창, 한국어 음성 출력, ScreenCaptureKit 1장 미리보기
- `tests/`: 자동 검증
- `.github/workflows/ci.yml`: Linux 코드 검증 + macOS Swift 컴파일

## 실행 (Mac)

**쉬운 실행:** macOS 14 이상이고 Xcode Command Line Tools와 Python 3가 준비돼 있다면 `START_JARVIS_MAC.command`를 더블클릭합니다. 서버와 네이티브 셸을 함께 시작합니다. 최초에는 macOS 보안 확인이 필요할 수 있습니다. 네이티브 화면 캡처는 시스템 권한 허용 후 직접 버튼으로 시작하세요.

**브라우저만 실행:** `START_JARVIS.command`를 더블클릭하거나 `python3 app.py` 실행. 브라우저에서 `http://127.0.0.1:8765`.

**개발자 테스트:** `python3 -m unittest discover -s tests -v`; `swift build --package-path macos`.

## 로컬 화면 글자 읽기 v1.8

Mac 앱 **화면** 탭에서 명시적으로 **화면 캡처 + 글자 읽기**를 누르면 Apple Vision을 이용해 한국어/영어 텍스트를 기기 내에서 인식하고 표시합니다. 자비스 자신의 창은 캡처에서 제외합니다. **외부 전송, 자동 기록, AI 이미지 이해는 없습니다.** 실제 Mac 화면 권한과 실캡처 성공은 앱에서 별도 승인·확인이 필요합니다. 자세히: docs/SCREEN_TEXT_V18.md.

## 로컬 화면 질문 v1.9

Mac 앱 화면 탭에서 OCR 글자를 대상으로 **오류 후보 찾기, 키워드 찾기, 텍스트 정리**를 실행할 수 있습니다. 기본 Mac 음성으로 결과 읽기도 가능합니다. 모두 Mac 앱 메모리 내부에서 처리하며 **외부 모델 호출이나 저장은 없습니다**. 이는 규칙 기반 텍스트 분석이지 화면 전체를 이해하는 AI가 아닙니다. 자세히: docs/SCREEN_QUESTIONS_V19.md.

## 선택 앱 UI 구조와 화면 글자 질문 v2.0

Mac 앱 **화면** 탭에 선택 앱의 접근성 UI 구조를 별도로 읽고 화면 OCR과 함께 질문하는 기능을 추가했습니다. 사용자가 명시적으로 앱을 선택하고 버튼을 눌렀을 때만 읽으며 **자동 클릭, 입력, 외부 전송, 기록 저장은 없습니다**. OCR은 전체 디스플레이, 접근성 UI는 선택 앱이므로 동일한 창이라는 보장은 없습니다. 실제 Mac 화면/접근성 권한 및 현장 조회는 아직 검증 대상입니다. 자세히: docs/UI_CONTEXT_V20.md.

## 승인 기반 1회 새로고침 v2.1

Mac 앱 **UI 구조** 탭에서 사용자가 직접 선택한 앱의 **새로고침** 버튼을 수동으로 확인하고, 별도 확인 대화상자에서 승인했을 때만 **AXPress 1회**를 시도할 수 있습니다. 저장·삭제·결제·발행·임의 클릭·문자 입력은 지원하지 않습니다. 새로고침도 미저장 내용이 사라질 수 있으므로 주의하세요. macOS 접근성 권한과 실제 외부 앱 조작 성공은 별도 실기기 검증이 필요합니다. 자세히: docs/APPROVED_REFRESH_V21.md.

## 프로젝트 작업 제안 → 승인 → 읽기 전용 실행 v2.2

Mac 앱의 **작업** 탭에서 등록 프로젝트의 로컬 상태를 보고, 공개 GitHub 상태 확인 작업을 **제안→승인→실행→영수증 확인** 순서로 진행할 수 있습니다. 조회 전 사용자가 직접 승인해야 하며, 저장소 변경·배포·자동 완료 판단은 하지 않습니다. 자세히: docs/APPROVED_PROJECT_WORK_V22.md.

## 로컬 프로젝트 기억과 다음 작업 v2.3

Mac 앱의 **작업** 탭에서 할 일을 직접 추가하고 **예정·진행·막힘·완료**로 수정하면 기존 SQLite에 보존합니다. 진행 중 → 예정 순서로 다음 할 일을 보여주고, **자비스** 대화에서도 특정 프로젝트의 다음 작업과 막힌 작업을 확인할 수 있습니다. 이것은 사용자가 기록한 작업 상태이며 실제 GitHub/AWS의 작업 완료를 의미하지 않습니다. 자세히: docs/PROJECT_CONTINUITY_V23.md.

## Mac 로컬 코드 확인 v2.4

Mac 앱 **작업** 탭에서 사용자가 직접 Git 저장소 폴더를 연결하면 로컬 브랜치, 현재 커밋, Git 변경 항목 개수를 읽기 전용으로 볼 수 있습니다. 폴더 연결은 이 Mac의 앱 설정에만 저장하며, 앱 시작 시 자동 검사하거나 외부 전송하지 않습니다. 원격 GitHub 상태·배포 여부와 동일하다는 주장을 하지 않습니다. 자세히: docs/LOCAL_GIT_STATE_V24.md.

## 프로젝트 인수인계 요약 v2.5

Mac 앱의 **작업** 탭에서 프로젝트 목표, 직접 기록한 다음 할 일·막힌 작업, 마지막 Mac Git 확인과 승인한 GitHub 확인의 브랜치·HEAD·확인 시각을 각각 구분해 보여줍니다. **인수인계 내용 복사** 버튼으로 필요한 내용을 사용자가 직접 복사할 수 있습니다. 요약 열기·복사로 새 Git/GitHub/AWS 조회나 작업 실행을 하지 않으며, AWS 배포 성공으로 판단하지 않습니다. 자세히: docs/HANDOFF_REPORT_V25.md.

## 승인 기반 프로젝트 작업 공간 열기 v2.6

Mac 앱 **작업** 탭에서 사용자가 연결한 Git 폴더와 등록 GitHub 저장소 중 원하는 대상을 선택하고, **작업 이어하기 제안 → 별도 승인**을 거쳐 Finder 또는 브라우저를 열도록 요청할 수 있습니다. GitHub 주소와 프로젝트·폴더 변경을 검사하며, 승인 없이 앱을 열거나 자동으로 코드 수정·푸시·배포하지 않습니다. OS가 열기 요청을 수락한 것과 실제 페이지 로딩을 구분합니다. 자세히: docs/WORKSPACE_RESUME_V26.md.

## Mac 음성·텍스트 명령을 프로젝트 제안에 연결 v2.7

Mac 앱 **음성** 탭에서 등록 프로젝트의 전체 이름과 "작업 이어서 열어줘"를 말하거나 입력하거나, **등록 프로젝트 선택** 메뉴에서 명령을 채우면, 로컬 프로젝트 기록에 맞는 **작업** 탭을 선택하고 Finder/GitHub 열기 제안을 표시합니다. **최종 승인이 있어야만** 실제로 엽니다. 자연어 일반 이해가 아닌 제한된 키워드 인식이며, 마이크 권한·실제 음성 전사는 별도 검증이 필요합니다. 자세히: docs/VOICE_WORKSPACE_ROUTING_V27.md.

## JARVIS 자기 프로젝트 기억 v2.8

Mac 앱 **음성** 탭에서 **자비스 다음 할 일** 버튼을 누르거나 "자비스, 다음 할 일 뭐야?"라고 말하면 정확히 등록된 **JARVIS eidis** 프로젝트의 로컬 작업 상태와 최근 등록된 미완료 작업을 간단히 알려줍니다. 별도 GitHub·배포 확인이나 코드 실행은 하지 않습니다. 프로젝트 이름을 명시하면 해당 프로젝트가 우선하며, "프로젝트 현황"은 전체 목록으로 처리합니다. 자세히: docs/SELF_PROJECT_PROGRESS_V28.md.

## 현재 한계

- 자연어 LLM 분석, AI 화면 이해, 범용 Mac 앱 조작(특정 버튼 1회 새로고침만 예외), 웨이크워드 상시 감지, iPhone·클라우드 연결은 **미구현**.
- macOS 네이티브 셸은 GitHub Actions에서 **컴파일 테스트**만 했으며 사용자 Mac의 권한·UI 실행은 별도로 검증해야 합니다.
- ScreenCaptureKit은 명시적으로 버튼을 눌러 1장을 캡처하고 미리보기만 제공하며 파일·외부 AI로 보내지 않습니다.
- 브라우저 Web Speech 음성 인식은 브라우저 공급자의 원격 처리가 포함될 수 있습니다.
- GitHub Actions는 테스트만 실행하고 자동 배포나 시스템 변경을 하지 않습니다.

자세한 기술 설계: `docs/ARCHITECTURE.md`; 디자인 생성과 API 동의: `docs/DESIGN_STUDIO_V07.md`; macOS 실행: `macos/README.md`.

## JARVIS CONSOLE v1.0
데스크톱 오른쪽(모바일은 하단 접이식)에 명령·로컬 활동·연결 오류를 모아 표시합니다. 중앙 작업 화면에 흩어졌던 활동 로그를 제거했습니다. **운영체제의 셸 로그는 수집하지 않습니다.** 자세한 범위: `docs/CONSOLE_V10.md`.


## 대화 맥락 / Brain v1.2
입력창과 Mac 음성 인터페이스가 공통 대화 API를 이용합니다. **이 실행 중의 최근 대화**를 RAM에서 유지하며, 명시적으로 저장한 SQLite 기억만 검색합니다. 기본적으로 LLM 추론은 비활성화이며, 별도 API 키·모델 지정·서버 허용·매 요청 동의가 있을 때만 유료 텍스트 모델 응답을 사용합니다. 실제 API 실호출은 별도 검증 대상입니다. 자세히: `docs/CONTEXT_BRAIN_V12.md`.


## Project Ledger v1.3
프로젝트/할 일/진행·막힘·완료를 사용자가 직접 기록하고 영구적으로 관리합니다. GitHub 확인은 **공개 저장소에 한해 버튼을 눌렀을 때만** 실행하며, 확인 시각과 실제 커밋/Workflow 증거를 작업 상태와 분리합니다. 자동 완료 판단이나 외부 API 과금은 하지 않습니다. 상세: docs/PROJECT_LEDGER_V13.md.


## Tools v1.4 — 읽기 전용 업무 실행
등록된 공개 GitHub 프로젝트에 대해 **명시적인 상태 확인 요청**이 오면, 허용 도구로 브랜치 HEAD·현재 SHA의 일부 Workflow를 읽고 실행/오류 기록을 남깁니다. 한 서버 실행당 최대 8회 조회, 무단 배포·수정·삭제 도구 없음. 별도 AI 요금 없음. 실제 사용자 Mac의 GitHub 인증/비공개 저장소 접근은 미구현. 자세히: docs/TOOLS_V14.md.


## Mac 실기기 진단 v1.5
앱의 진단 탭에서 버튼을 눌러 Mac 권한 상태·localhost 서버·SQLite 읽기·등록 도구 상태를 권한 요청이나 외부 API 호출 없이 확인할 수 있습니다. START_JARVIS_MAC.command는 서버 HTTP 준비를 확인한 다음 앱을 열도록 변경했습니다. 실제 마이크·화면·GitHub 조회 성공은 사용자 Mac에서 각각 수동 시험해야 합니다. 상세: docs/MAC_READINESS_V15.md.


## Mac 음성 출력 설정
Mac 앱의 음성 탭에서 **설치된 한국어 목소리 선택, 속도/음높이 조절, 미리 듣기**가 가능합니다. 설정은 UserDefaults에 보존되며 모든 네이티브 음성 응답에 동일하게 적용합니다. 별도 유료 TTS API 호출 없음. 자세히: docs/VOICE_SETTINGS_V16.md.


## ElevenLabs 선택 음성 (기본 OFF)
Mac 앱 음성 탭에서 제공받은 Voice ID를 기본 입력하고, macOS 키체인에 API 키를 직접 저장하면 ElevenLabs 미리 듣기와 유료 음성 출력을 선택적으로 활성화할 수 있습니다. API 키를 저장해도 자동 호출하지 않으며 5회/실행·600자/응답 제한과 Mac 기본 음성 대체 기능이 적용됩니다. 앱에서 실제 유료 요청을 아직 시험하지 않았습니다. 상세: docs/ELEVENLABS_V17.md.
