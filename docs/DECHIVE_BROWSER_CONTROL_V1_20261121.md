# DECHIVE BROWSER CONTROL 1.0 — Mac WebKit 실행 기록

작업일: 2026-11-21 / 로컬 자비스

## 구현 개요
- 기존 DECHIVE 전체화면의 `JarvisEmbeddedBrowser`를 확장. Chrome/Safari 현재 탭이나 로그인 프로필은 사용하지 않음. `WKWebsiteDataStore.nonPersistent()`로 매번 별도 임시 웹 세션을 사용하며, 자비스 브라우저를 닫으면 숨겨짐.
- 명시적으로 입력한 `https://` 웹주소를 실제 WebKit에서 열고, 페이지가 로드된 것을 이벤트와 실제 최종 URL·제목으로 확인한 후에만 성공 보고.
- 현재 화면에 **실제로 보이는** 링크의 제목 및 URL만 DOM에서 읽는다. 출처 페이지가 현재 화면에 없거나 로딩 중이면 링크 목록을 만들지 않는다.
- 표시된 동일 사이트의 링크에 1~12 번호를 붙인다. 사용자가 번호로 선택하면 해당 GET URL로 이동하고 실제 완료 이벤트와 최종 URL 확인 후 결과를 안내. 다른 도메인, 로그인/계정, 구매/결제/삭제 등이 표시된 경로 및 쿼리, fragment-only 링크는 자동 링크 목록에서 제외.
- 웹페이지의 `input[type=search]` 또는 `role=searchbox` 중 표시되고 활성화된 검색창 하나에만 사용자가 지정한 문구를 입력한다. JS 코드에 문자열을 삽입하지 않고 `callAsyncJavaScript(arguments:)`로 전달하며, 실제 입력된 값이 같은지 검증한다. **폼을 제출하거나 Enter를 자동으로 누르지 않는다.** 다만 웹페이지 자체의 검색 자동완성·스크립트에 의한 후속 요청은 사이트가 실행할 수 있으므로 외부 데이터 전달 가능성을 인지해야 한다.
- 위/아래 스크롤 시 실제 스크롤 위치 변화 전/후를 확인하고, 화면에 다시 나타난 링크 목록만 유효하게 관리. 오래된 화면의 링크 번호는 사용 불가.
- 실제 상태 확인은 기존 WebKit 실제 URL/제목 기반. 응답 400 이상의 HTTP 페이지를 성공으로 표시하지 않도록 차단하고, 실패 시 성공을 주장하지 않는다.
- 화면 패널의 상단에 `BROWSER CONTROL / 실제 동작 확인`과 최근 동작의 실제 확인 결과, 링크 목록 일부 표시. 기존 금빛 코어 영상, 음성 대화 및 UI 프레임은 유지함.
- 브라우저 내용과 링크는 신뢰하지 않는 데이터이다. Qwen이 자유롭게 DOM 명령을 생성하거나 JavaScript를 실행하도록 허용하지 않고, 엄격한 규칙으로 인식한 명령만 실행.
- 등록된 API 키와 유료 모델을 새로 사용하지 않음. 이 구현은 **Work형 자율 에이전트가 아니라 사용자 명령 한 건씩 실행하는 제한형 브라우저 제어**.

## 사용 가능한 음성 예시
1. `자비스, 브라우저에서 https://www.python.org/ 열어줘.`
2. `자비스, 현재 페이지 확인해줘.`
3. `자비스, 링크 목록 보여줘.`
4. `자비스, 링크 4번 열어줘.` (실제 확인된 번호)
5. `자비스, 검색창에 Python documentation 입력해줘.`
6. `자비스, 스크롤 내려줘.` / `자비스, 스크롤 올려줘.`

## 안전 경계
- 자동 주소 접근은 공개된 HTTPS 호스트 이름, 기본 HTTPS 포트(443)만 허용. loopback/내부 주소, 인증정보가 URL에 든 경우, 직접 IP 주소, 일부 사설 DNS 재매핑 이름을 차단한다. 기존 WebKit 네비게이션 delegate도 비 HTTPS 주소를 거부한다.
- **제한 사항:** DNS 리바인딩에 대한 완전한 샌드박스가 아니며, 공개 도메인 자체가 악성이라면 웹사이트 스크립트는 네트워크 요청을 할 수 있다. URL 문자열 검사만으로 무해한 사이트라고 보장할 수 없다. 같은 사이트의 GET 링크도 운영 방식에 따라 서버 동작을 일으킬 수 있으므로 외부 플랫폼에서 민감한 작업은 별도 승인 기반 도구가 필요하다.
- 원격 게시·결제·삭제, 일반 폼 제출, 비밀번호/OTP/카드 입력, 화면 좌표 무차별 클릭, 기존 Chrome/Safari 프로필 접근, Mac 시스템 앱 제어는 **구현하지 않음**.
- 이번 단계 동작 결과는 현재 음성 대화와 화면 패널의 일시적 기록으로 확인한다. 별도의 영구 브라우저 실행 감사 로그는 추후 추가해야 한다.
- 다른 서비스의 실제 API 갱신 주기, 개인 DB, 검색/검증 코어 설정은 변경하지 않음.

## 실제 Mac WebKit 시험
- `macos/tests/browser/live.swift`를 독립 GUI 테스트로 실행. 네트워크 접근이 있는 공개 `https://www.python.org/`에 테스트용 임시 WebKit을 띄움. 개인 브라우저 쿠키나 사이트 계정을 사용하지 않음.
- 실제 페이지 제목 `Welcome to Python.org`, 도메인 및 링크 목록 9개 발견.
- 검색창에 `Python package documentation` 문구를 실제 입력한 값을 검증. 사이트에 제출/검색하지 않음.
- 페이지 위/아래 스크롤이 실제 이동했다는 결과 확인. 스크롤 이전 링크 번호로 이동하려는 명령은 거부.
- 현재 화면에서 PSF 링크 선택. 요청 URL에서 `https://www.python.org/psf-landing/`으로 공식 사이트 내 리디렉션된 것을 실제 WebKit navigation 완료·주소·제목으로 확인. 결과 `Python Software Foundation` 페이지의 실제 제목 표시.
- 네비게이션 완료 이벤트와 실제 주소 확인 전에는 성공이라고 말하지 않도록 수정; 리디렉션의 최종 URL도 실제 URL로 표시.
- `macos/tests/browser/main.swift`는 사용자 명시 명령만 파싱, 부정·질문 차단, 비공개/HTTP/localhost 링크 거부, 외부 사이트 이동 제한 등 스모크 테스트 수행.
- 실제 설치 앱에서 음성 마이크로 명령을 지속 호출하며 발생할 수 있는 UI/성능 문제는 아직 확인되지 않았다. 실제 음성/사용자 화면 검증은 별도 필요.
