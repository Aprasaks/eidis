# JARVIS 실시간 받아쓰기 — 중간 휴식 시 기존 문장 보존

## 사용자 실기기 피드백
질문은 전송되지만 중간에 쉬면 이전에 받아 적은 문장이 새 문장으로 다시 써지는 현상이 보고됨. 이는 Apple Speech 인식기의 임시 전사를 매 이벤트마다 전체 덮어쓰던 코드, 그리고 짧은 무음 자동 전송 정책과 관련될 수 있음. 실제 원인별 발생 비율은 아직 확인되지 않음.

## 수정
1. `JarvisSpeechTranscriptAssembler` 추가. 확정된 인식 구간은 별도로 누적하고, 새 인식 구간의 임시 부분만 교체. 서로 다른 구간을 하나의 질문으로 연결.
2. `LocalSpeechListener`가 `result.isFinal`을 받으면 이전 구간을 확정해 보존하고, 기존 AVAudioEngine 마이크 탭을 유지한 상태에서 새 Speech 인식 요청을 연결. 지연된 이전 인식 콜백은 `recognitionEpoch`으로 차단.
3. `JarvisSpeechAudioRelay`에서 음성 버퍼를 새로운 인식 요청에 연결, 세션 종료나 취소 시 종료/무효화.
4. 자동 전송 대기 기본값 3.5초 → 6.5초. 종전 2.5~5초 설정은 앱 시작 시 최소 6.5초로 상향 이행. 새 조절 범위는 5~12초.
5. 오래 이야기할 때에는 LIVE DIALOGUE 패널에서 '말을 멈추면 자동으로 질문 확정'을 꺼서 Space로 전송할 수 있도록 화면 안내.
6. 기존 대화 컨텍스트, Mac Keychain, SNS/API, 금빛 코어, 창 배치 변경 없음.

## 검증
- Swift 빌드 및 Python 회귀 테스트 수행.
- `macos/tests/voice/main.swift`에 같은 질문에서 '자비스 오늘 아침에는' (첫 구간 확정) + '잠깐 쉬었고 다시 말했어' (두 번째 구간) 누적 테스트 추가.
- 실제 마이크에서 Apple Speech가 구간을 끝내는 타이밍과 다음 구간의 인식 결과를 사용자가 확인해야 함. 라이브 음성 입력 품질 자체를 미리 보증하지 않음.

## 직접 검증 절차
- 새 JARVIS 전체화면에서 LIVE DIALOGUE를 열어 "자비스, 오늘 아침에는"을 말한 뒤 2~3초간 쉬고 "조금 늦게 일어났어"라고 이어서 말한다.
- 두 문장이 하나의 LIVE TRANSCRIPT에 순서대로 남는지 확인.
- 자동 확정 OFF에서도 동일한 시험을 한 뒤 Space로 전송한다.
- 긴 정지 후 자동 확정되는 것이 불편하면 OFF로 사용한다. 음성만으로 발화 종료를 완벽히 구분하는 기능은 아직 구현되지 않음.
