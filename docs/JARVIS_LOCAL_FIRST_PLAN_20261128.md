# JARVIS 로컬 우선 운영 기획서 — 2026-11-28

## 1. 목표

일하고, 프로젝트를 하고, 블로그를 쓰는 동안 **옆에서 같이 대화하는 자비스.**
API 크레딧 없이 운영하고, 쓸 수 있는 건 구독 요금제(Claude Pro, ChatGPT Plus, Gemini)와 이 맥뿐이다.

## 2. 운영 원칙

1. **자비스의 몸과 입은 로컬이다.** 대화의 90% 이상은 코드, 로컬 임베딩, Qwen 9B 안에서 끝낸다.
2. **구독 CLI는 가끔 부르는 비싼 전문가다.** Codex는 코드, Claude는 설계·리뷰·글, Gemini는 긴 문서·웹 리서치를 맡는다. 사용자가 명시적으로 시킬 때와 밤 작업 대기열에서만 쓴다.
3. **자비스는 대시보드가 아니다.** 기능은 말로 꺼내 쓰는 능력이다. 패널은 말로 설명하기 어려울 때만 잠깐 띄운다.
4. **끼어들지 않는다.** 먼저 말을 거는 건 조건에 걸릴 때만 하고, 대화가 끊긴 틈에만 한다.
5. **승인한 것만 배운다.** Qwen이 학습 제안을 하고, 사용자가 승인한 것만 반영한다(기존 원칙 유지).
6. 구독 CLI는 공식 CLI 그대로 본인용으로만 쓴다. CLI 로그인 토큰을 꺼내 API처럼 호출하지 않는다.

### 처리 단계

| 단계 | 담당 | 처리하는 일 | 비용 |
|---|---|---|---|
| 0 | 코드: 규칙과 템플릿 | 시간, 알람, 패널 조작, 날씨·주식 문장 만들기 | 무료, 즉시 |
| 1 | 로컬 임베딩(bge-m3) | 어떤 기능을 원하는지 판별 | 무료, 수십 ms |
| 2 | 로컬 Qwen 9B | 일상 대화, 동작·인자 추출, 요약, 말투 다듬기 | 무료 |
| 3 | 구독 CLI | 코딩, 깊은 리서치, 긴 문서 | 사용 한도 소모 |

## 4. 작업 목록

### P0. Qwen 상주 ⭐ 최우선

**측정값** (qwen3.5:9b-q4_K_M, 24GB 맥)

| 상황 | 응답 시간 |
|---|---|
| 처음 올릴 때 | 6.0초 |
| 이미 올라와 있을 때 | 0.06초 |
| `num_ctx`만 바꿔서 요청 | 1.2~1.5초 (매번 다시 올라감) |

메모리 점유는 약 4.7GB(num_ctx 4096 기준)다.

**현재 흩어진 설정**

| 파일 | keep_alive | num_ctx |
|---|---|---|
| `JarvisOverlayConversation.swift:888` (일상 대화) | 2m | 4096 |
| `JarvisOverlayConversation.swift:1324` / `:1335` | 2m | 4096·6144 / 2048·4096 (thinkingMode별) |
| `JarvisOverlayConversation.swift:1565` | 2m | 4096 |
| `JarvisThinkingCore.swift:548` | 10m | 6144 |
| `JarvisResearchVerification.swift:297` | 10m | 6144 |
| `JarvisLearningMemory.swift:289` | (없음) | 2048 |
| `JarvisLocalModelWarmup.swift:26` | 2m | — |

**작업**
- **Q1. 설정 한 곳에 모으기**: `JarvisQwenSettings` 파일을 새로 만들고 모델 이름, `num_ctx`, `keep_alive`를 둔다. 모든 Ollama 호출이 이 값을 쓴다.
  - `num_ctx`는 하나로 통일한다(후보 6144).
  - `num_predict`와 `temperature`는 기능별로 달라도 된다. 재로딩을 일으키지 않는다.
- **Q2. 하트비트로 상주시키기**
  - 앱이 실행되면 바로 워밍업한다.
  - 10분마다 짧은 요청(`keep_alive: 30m`)을 보내 상주 시간을 연장한다.
  - 정상 종료할 때는 `keep_alive: 0`을 보내 즉시 내린다.
  - "영원히(-1)"로 하지 않는 이유: 알려진 크래시로 앱이 죽으면 모델이 계속 남는다. 하트비트 방식이면 30분 뒤 자동으로 내려간다.
- **Q3. 깨우는 말로 미리 데우기**: 깨우기 데몬이 "자비스"를 감지하면 음성 인식과 동시에 워밍업 요청을 보낸다.

**완료 기준**
- 앱을 켜고 30분 동안 말을 안 걸어도 첫 응답이 0.2초 안에 시작된다.
- 대화, 생각 기록, 학습 기능을 오가도 `ollama ps`의 CONTEXT 값이 바뀌지 않고 재로딩이 없다.
- 앱을 종료하면 `ollama ps`에서 모델이 바로 사라진다. 앱이 강제 종료되면 30분 안에 사라진다.

**결정 필요**
- 통일할 `num_ctx` 값(6144 vs 4096). 6144일 때 메모리 점유를 측정한 뒤 정한다.

### P1. CLI 완료 알림 (알림 대기열)

- **N1.** `JarvisAgentTerminalBay`에서 프로세스 종료를 감지하고 결과를 모은다. Claude·Gemini는 stream-json의 마지막 result를, Codex는 `-o` 결과 파일을 쓴다.
- **N2.** Qwen이 결과를 1~2문장으로 요약한다.
- **N3.** 전달 규칙

| 상황 | 동작 |
|---|---|
| 사용자가 말하는 중이거나 자비스가 답하는 중 | 대기열에 넣었다가 대화가 끊기면 말하기 |
| 텍스트로 일상 채팅 중 | 소리 없이 채팅 메시지로 표시 |
| 자비스 창이 숨겨진 상태 | 맥 알림 + 짧은 음성 한 줄 |
| 실패 | 원인을 한 줄로 말하기 |

  - 자세한 내용은 "자세히 말해줘"라고 할 때만 결과 패널을 연다.
- **N4. 조용히 무시되는 요청 없애기**: 지금 밤 작업 중에 `runReadOnly`를 요청하면 아무 말 없이 무시된다. 이유를 말하게 바꾼다.
- 이 대기열은 P4(먼저 말 걸기)와 같은 통로로 재사용한다.

**완료 기준**: CLI 작업을 맡기고 대화를 계속하는 중에 작업이 끝나면, 대화가 끊긴 틈에 요약을 한 번만 말한다.

- **S6. (나중) 미세조정**: 예문이 수백 개 이상 쌓인 뒤에도 S4·S5로 안 되는 경우에만 한다. 먼저 임베딩 위에 작은 분류기를 학습시켜 보고, 그래도 부족하면 MLX-LM LoRA를 쓴다.
- 권한 등급: `read`는 바로 실행, `writeLocal`은 저장 전에 보여주기, `external`(게시·전송)은 반드시 확인받기.

### P6. 이디스 자율 운영 (SNS)

기반은 이미 있다: 01:30 캐러셀 제작, 폰 승인, 22:00 인스타와 09:00 Threads 자동 게시, 매시간 성장 기록.
