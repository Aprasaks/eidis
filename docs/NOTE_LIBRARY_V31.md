# JARVIS v3.1 — 저장된 실행 메모 다시 찾기

## 목적
JARVIS v3.0에서 만든 실행 메모를 나중에 찾아 **읽을 수 있는 기능**입니다. 아직 메모를 자동 편집하거나 이어쓰기·작업 실행을 하지는 않습니다.

## Mac 사용법
1. **JARVIS → 작업**에서 기록을 확인할 프로젝트를 고릅니다.
2. 기존에 연결한 Git 폴더가 없다면 **Git 폴더 연결**로 직접 선택합니다.
3. **다음 할 일 시작 → 저장된 메모** 또는 **내 작업 기록 → 메모 보기**를 누릅니다.
4. **작업 실행 메모** 영역에서 해당 작업의 메모 목록을 확인합니다.
5. 원하는 파일 옆의 **내용 읽기**를 눌러 본문을 표시합니다. 텍스트는 선택하여 수동 복사할 수 있습니다.

## 제한과 보호
- 임의 폴더 검색이 아니라 사용자가 연결한 Git 루트의 `.jarvis/notes`만 읽습니다.
- 파일명은 선택한 작업 ID를 포함하는 `task-<id>-<8자리 대문자 16진수>.md` 형식만 허용합니다. 다른 작업의 메모나 임의 경로는 읽지 않습니다.
- 심볼릭 링크로 바뀐 디렉터리·파일은 따르지 않습니다. 열린 파일이 일반 파일인지 재검사합니다.
- 메모 목록에서 최대 **20개**를 최신 수정 시각 순으로 보여줍니다. 파일은 최대 **16KB**까지만 읽습니다.
- 메모가 아직 없는 프로젝트라면 빈 목록을 표시하며 파일이나 폴더를 만들지 않습니다.
- 완료·막힘 작업의 기존 메모도 읽을 수 있지만, 새 메모 생성은 예정·진행 작업에서만 허용합니다.
- 외부 모델·GitHub API 호출, 자동 파일 변경, 커밋, 배포, OS 앱 열기 없음.
- **읽기 전용**이라는 점이 중요합니다. 수정·이어쓰기는 아직 지원하지 않습니다. 실제 Mac UI 버튼 클릭의 사용자 확인은 별도입니다.

## 검증
임시 Git 폴더에 v3.0 방식으로 직접 생성한 메모를 다시 목록에서 찾아 읽고, 내용 일치를 검증했습니다. 다른 작업 번호·경로 문자열·심볼릭 링크 파일·과대 파일 및 안전하지 않은 디렉터리는 제외·차단하는 Swift 테스트가 통과했습니다. 실제 사용자의 프로젝트 메모는 자동으로 읽거나 공개하지 않았습니다.
