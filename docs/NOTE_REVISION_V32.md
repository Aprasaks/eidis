# JARVIS v3.2 — 실행 메모 수정본으로 이어쓰기

## 목적
JARVIS v3.1에서는 기존 Markdown 실행 메모를 읽기만 했습니다. v3.2에서는 내용을 편집하고 **원본을 덮어쓰지 않고 새 버전으로 저장**합니다. 실제 작업, 코드 변경, Git 커밋, 배포를 자동 실행하지 않습니다.

## Mac 사용법
1. JARVIS **작업** 탭에서 사용자가 연결한 Git 프로젝트와 할 일을 선택합니다.
2. **메모 보기 → 내용 읽기 → 이 메모 수정본 작성**을 선택합니다.
3. 불러온 Markdown을 편집하고 **수정본 전체 미리보기**를 눌러 새 파일 이름과 내용을 확인합니다.
4. **새 수정본 저장 승인 화면 → 승인하고 수정본 새 파일 저장**을 직접 누르면, 해당 Git 폴더의 `.jarvis/notes/task-<작업 ID>-<새 8자리 코드>.md`로 기록합니다.
5. **메모 목록 새로 읽기**를 누르면 원본과 새 버전을 각각 볼 수 있습니다.

## 명확한 동작 경계
- 기존 원본 파일을 수정하거나 덮어쓰지 않습니다. 편집한 새 버전은 독립된 Markdown 파일이며, 상단 주석에 원본 파일명을 남깁니다.
- 원본·수정본 내용이 같거나 공백뿐이면 새 저장 제안을 만들지 않습니다.
- 승인 기한은 **2분**입니다. 승인 후 서버의 프로젝트/작업 기록을 다시 확인합니다.
- 저장 직전 같은 작업의 원본을 안전하게 다시 읽고, 사용자 편집 시작 시점의 내용과 정확히 비교합니다. 다르면 새 버전을 만들지 않습니다.
- 저장은 기존 v3.0의 O_EXCL·O_NOFOLLOW 보호 및 쓰기 후 내용 검증을 사용합니다. 기존 파일명 충돌이 나도 재시도·덮어쓰지 않습니다.
- 문서는 최대 **16KB**이며 기존 메모와 수정본 모두 저장된 Git 프로젝트 폴더 내부에서만 접근합니다.
- 완료·막힘 작업은 과거 메모를 계속 읽을 수 있지만 새 수정본을 작성할 수 없습니다.
- 사용자가 나중에 이 Git 폴더를 커밋할 경우 메모가 포함될 수 있습니다. .gitignore와 Git 기록을 자동 변경하지 않습니다.

## 검증
Mac의 별도 임시 Git 폴더에서 이전 메모를 실제로 생성·읽고, 수정본을 새 파일에 저장했습니다. 원본 동일성, 새 버전 목록, 새 파일 중복 금지, 2분 기한, 다른 프로젝트/경로 차단, 원본 외부 변경 충돌, 무효 파일 이름 및 크기 제한 테스트를 수행했습니다. 실제 사용자 프로젝트 메모를 읽거나 수정하지 않았습니다. 실제 네이티브 버튼 클릭은 사용자 승인과 별도 실사용 확인이 필요합니다.
