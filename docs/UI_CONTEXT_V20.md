# JARVIS v2.0 — 선택한 앱 UI 구조 + 화면 글자 질문

## 사용 흐름
1. JARVIS 앱의 **화면** 탭을 열어 사용자가 원할 때 **화면 캡처 + 글자 읽기**를 누릅니다. ScreenCaptureKit으로 한 장을 읽고 Apple Vision으로 한국어·영어 OCR을 로컬 처리합니다.
2. **선택한 앱의 버튼·탭 구조 읽기**에서 앱을 선택한 다음 **접근성 권한 요청** 및 **선택 앱 UI 구조 읽기**를 직접 실행합니다. 승인하지 않으면 읽을 수 없습니다.
3. **화면 글자에 질문하기**에서 "이 앱에 어떤 버튼이 있어?", "화면 오류가 뭐야?" 등을 묻습니다. UI 질문은 사용자가 명시적으로 조회한 선택 앱의 접근성 역할/버튼 제목만 참조합니다. 오류 질문은 OCR 텍스트의 오류 관련 문구만 참조합니다.

## 동작과 구분
- **OCR**: 디스플레이 한 장의 글자. **앱 UI**: 사용자가 선택한 하나의 실행 앱의 일부 접근성 구조. *둘이 같은 창이라는 보장은 없습니다.*
- UI 조회는 AX 역할과 버튼/메뉴/탭 등의 제목 일부로 제한하고 입력창 값·암호·문서 본문은 읽지 않습니다.
- 앱을 바꾸면 직전 앱의 UI 조회 결과와 이전 답변을 자동으로 무효화합니다.
- 두 기능 모두 명시적인 버튼 조작에만 응답하고 상시 감시, 자동 클릭, 입력, 원격 API 호출, 로그/DB 저장을 하지 않습니다.
- 사전에 정의된 규칙에 따른 로컬 질문 응답이며 시각적 레이아웃, 아이콘, 그래프, 이미지 의미와 정확한 좌표를 추론하는 멀티모달 모델은 아닙니다.
- UI 정보가 제한되거나 권한이 없으면 결과를 만들지 않습니다. 패스워드·API 키 등을 나타내는 문자열이 답변에 표시되지 않도록 기본 차단하지만 민감 정보 탐지는 완전하지 않으므로 화면에 비밀을 표시한 채 사용하지 마세요.

## 검증 현황
- 소스 빌드와 앱 패키징 성공.
- 기존 Python 단위 테스트 통과.
- 합성한 UI 컨트롤과 OCR 문자열로 로컬 질의, 정보 숨김, 명시적인 UI 조회 부재 시 폴백 검증.
- 실제 화면 기록 및 접근성 권한, 실제 앱 조회는 사용자가 Mac 시스템 설정에서 직접 승인하고 앱 버튼으로 확인해야 합니다.

## 남은 개발
이미지/아이콘/도표 내용 이해, 특정 컨트롤의 위치 확인, 승인 기반 클릭, 원격 iPhone 접근 등은 아직 구현되지 않았습니다.
