# JARVIS LIVE DIALOGUE v1 — 2026-11-20

## 핵심 목표
금빛 JARVIS 코어와 기존 전체 대시보드를 유지하면서, 발화를 실시간으로 받아 적고, 답변 중 끼어들기와 연속 대화 흐름을 지원한다. 실제로 확정되지 않은 말을 AI가 예측해 사용자 발화로 위장하지 않는다.

## 구현됨
- `NativeSpeech.swift`의 기존 한국어 온디바이스 인식 부분 결과(`shouldReportPartialResults=true`)를 Combine으로 구독한다.
- `JarvisLiveDialoguePanel.swift`를 추가해 실시간 임시 전사, 사용자 확정 발화, JARVIS 응답, 답변 중단 상태를 세션 안에서 구분해 표시한다.
- 기본 Core Mode의 우측에 LIVE DIALOGUE 패널을 넣고, `전체 대시보드` 중에는 좌측 코어 아래에 배치한다. LIVE CHECKS 터미널은 축소되지만 보존한다.
- 사용자가 말을 한 뒤 부분 전사 변경이 약 2초 멈추면 기존 `listener.finish()` 검증 절차로 질문을 자동 확정한다. Space / 마이크 버튼으로 명시적 확정도 가능하다.
- 자동 확정 스위치를 끌 수 있고, 마이크 일시정지 버튼으로 음성 인식을 중단한다.
- 답변 생성 중이나 ElevenLabs/Mac 음성 출력 중 Space/마이크 버튼을 누르면 기존 생성 요청과 음성을 취소하고 새 사용자 발화를 받는다. 텍스트 전송도 이전 응답을 중단하고 새 질문으로 바꿀 수 있다.
- 기존 Qwen 대화 메모리(최근 8개 role 항목), 패널 작업 상태, 실제 응답만 기록하는 원칙, 개인정보 보호가 유지된다.
- 대화 텍스트는 현재 풀스크린 세션의 메모리 안에서만 유지하고 Esc/닫기 시 삭제한다. 원시 음성·부분 전사는 별도 서버나 파일에 저장하지 않는다.
- 일상 잡담용 시스템 안내를 보완해 질문마다 기계적으로 호응하는 것 대신 실제 대화 맥락을 따르도록 했다.

## 검증됨
- Swift `swift build --package-path macos -c debug` 성공.
- Python unittest `discover -s tests`: 205건 통과. 신규 LIVE DIALOGUE UI/상태/중단/오디오와 기존 대시보드 회귀 계약 포함.
- 음성 입력과 에코·실제 대화 속도는 사용자의 맥 마이크 실기기 검증을 별도로 진행해야 함.

## 한계
- **아직 음성만으로 자동 barge-in을 지원한다고 주장하면 안 됨.** JARVIS가 이미 말하고 있을 때는 Space / 마이크 버튼 / 텍스트 입력으로 끼어들도록 구현. 마이크를 동시에 열면 JARVIS 자체 스피커 음성을 사용자 발화로 오인할 수 있어 AEC·VAD 실측 후 추가한다.
- 다음 단어 예측 기능은 미구현. 현재 화면은 실제 인식된 말만 실시간 전사하고, 임시 결과는 임시라고 명시한다.
- 자동 무음 구간 2초는 문장 중간의 긴 쉼도 턴 종료로 해석할 수 있으므로 실측으로 조정. 수동 확정 모드로 전환 가능.
- Qwen 모델은 로컬 연결 상태에 따라 응답 속도와 자연스러움이 달라지며, ElevenLabs 실패 시 기존 Mac 음성 대체 동작을 따른다.

## 직접 확인 절차
1. JARVIS 실행 후 `⌘⌥J`로 전체화면 호출.
2. 마이크 권한이 허용되면 LIVE DIALOGUE 패널에서 `LISTENING` 확인.
3. `자비스 오늘 뭐하고 있어?`라고 말해, 부분 전사가 즉시 나타나고 2초 뒤 확정 사용자 발화 및 AI 답변으로 바뀌는지 확인.
4. JARVIS가 말할 때 Space 또는 `응답 중단 · 내가 말하기`를 눌러 새로운 발화로 바뀌는지 확인.
5. `말을 멈추면 자동으로 질문 확정`을 껐다가 다시 켜고, 스페이스로 수동 확정되는지 확인.
6. `전체 대시보드 열어` 명령 후 좌측에 LIVE DIALOGUE·LIVE CHECKS가 함께 나타나는지 확인.
7. `마이크 일시정지` 및 Esc로 인식 중단과 세션 종료를 확인.
