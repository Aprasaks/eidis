# S2 / macOS 접근성 UI 구조 읽기 (read-only)

> 이 단계는 실시간 AI 화면 이해가 아닙니다. 명시적 사용자 선택 후 macOS가 제공하는 접근성 메타데이터 일부를 보는 기능입니다.

## 구현된 경계
- 앱의 'UI 구조' 탭에서 사용자가 **실행 중인 대상 앱**을 선택합니다.
- '접근성 권한 요청' 버튼은 macOS 손쉬운 사용(Accessibility) 권한을 요청합니다. 승인 여부는 OS가 결정합니다.
- '화면 구조 읽기' 버튼을 눌렀을 때만 AXUIElement로 해당 앱의 활성 창(가능할 때) 메타데이터를 읽습니다.
- 읽는 항목: 역할(role), 하위 역할(subrole), 안전하다고 판단된 제목(title), 계층 깊이. 보이는 모든 UI를 보장하지 않습니다.
- 입력 영역(텍스트 필드, 편집 영역, 보안 입력 등)의 제목·값·선택 텍스트는 요청하지 않습니다. **어떤 요소에서도 AXValue / SelectedText / 문자열 입력 내용은 수집하지 않습니다.**
- 한 번의 요청에서 **최대 80개**, 깊이 **최대 3**, 각 요소의 하위 **최대 12개**만 처리합니다.
- 정보는 앱의 메모리 내 리스트에만 표시됩니다. JSON API, 파일, 클라우드, 외부 모델로 보내지 않습니다.
- '기록 지우기' 또는 앱 종료로 메모리 내 결과를 지울 수 있습니다.
- 클릭/입력/스크롤/제어를 위한 AXUIElementPerformAction/SetAttributeValue 호출은 없습니다.

## 실제 Mac 검증 순서
1. 'START_JARVIS_MAC.command'로 실행. CI 컴파일은 macOS 권한 동작을 검증하지 않습니다.
2. 메모장/브라우저 등 민감하지 않은 일반 앱을 열고 자비스에서 'UI 구조' 탭으로 이동합니다.
3. '앱 목록 새로고침' → 해당 앱 선택 → '접근성 권한 요청' → macOS에서 승인.
4. 자비스로 돌아와 '화면 구조 읽기'를 눌러 역할과 제목이 표시되는지 확인합니다.
5. 입력창의 실제 텍스트나 비밀번호가 표시되지 않는지 확인합니다. '기록 지우기'로 지웁니다.
6. macOS에서 접근성 권한을 끄고 다시 시도해 안내가 정상적으로 나타나는지 확인합니다.

## 한계 및 보안
- 접근성 **앱 이름·버튼 제목도 민감할 수 있습니다**. 사용자가 명시적으로 앱을 고른 경우에만 읽고 외부로 내보내지 않습니다.
- 화면에 보이는 모든 UI를 읽을 수 있다는 의미가 아닙니다. 앱마다 AX 정보의 품질·제공 범위가 다릅니다.
- 접근성 API의 동기 호출은 앱 상태에 따라 멈칫할 수 있습니다. 조회량·깊이 제한과 메시징 타임아웃을 둡니다.
- 이 기능의 성공만으로 실제 화면 이해, 명령 실행, UI 조작이 완성됐다고 주장하지 않습니다.
- macOS의 손쉬운 사용 권한은 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 해제할 수 있습니다.
