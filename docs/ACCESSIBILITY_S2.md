# S2 · 읽기 전용 macOS UI 구조 살펴보기 (v0.8)

JARVIS의 'UI 구조' 탭에서 사용자가 대상 앱을 선택하고, macOS의 **손쉬운 사용 권한**을 명시적으로 승인한 뒤, '화면 구조 읽기'를 눌렀을 때만 한번 읽습니다.

## 검사하는 것
- 앱의 활성 창에 포함된 접근성 구조(역할, 하위 역할, 계층)
- 일부 **버튼/메뉴/체크박스/탭** 제목
- 최대로 80개, 깊이 3, 요소별 하위 12개, 요소당 메시징 타임아웃 0.25초

## 의도적으로 하지 않는 것
- 창/문서 제목, 페이지 본문, 입력값, 비밀번호, 선택 텍스트 읽기
- OCR/스크린샷 분석, 지속 관찰, 외부 API/모델 전송, 서버 저장
- 클릭/타이핑/스크롤 또는 다른 앱의 상태 변경

앱이 제공하는 접근성 정보가 부정확하거나 없는 경우 읽지 못할 수 있습니다. 버튼 이름 자체가 민감할 수 있으므로 사용자가 신뢰하는 앱을 직접 선택해야 합니다.

## 개발 및 검증
Swift 6 macOS 빌드 오류였던 CFTypeRef → AXUIElement 변환 전에 **CFGetTypeID**로 타입을 비교하고 캐스팅합니다. CI 성공은 컴파일과 패키징만 의미하며, 실제 Mac 권한 승인과 앱별 동작을 입증하지 않습니다.

검증 순서:
1. Mac에서 `START_JARVIS_MAC.command`로 실행
2. 'UI 구조' 탭 → 앱 선택 → '접근성 권한 요청' 클릭
3. macOS 시스템 설정에서 허용한 다음 자비스에서 '화면 구조 읽기' 클릭
4. 버튼/메뉴 이름이 표시되고 비밀번호나 문서 본문은 표시되지 않는지 확인
5. '기록 지우기' 버튼으로 목록을 비움

현재 `DECHIVE.local` 오프라인이므로 위 실기기 단계는 완료 상태가 아닙니다.
