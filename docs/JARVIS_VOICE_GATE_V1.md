# Experimental local voice filter
- Owner enrollment retained unchanged. User-reported held-out long sentences .734/.720/.801; short calls .335/.325/.440; additional sentence .671. Three synthetic nonowner short scores .092/.171/.090; long .148/.387/.146. Two user-reported media long scores .125/.058. These are cosine similarities, not probabilities. Provisional thresholds .25 wake/.52 command, not calibrated population error rates.
- Standby worker checks the existing DEKA detector and a bounded 1.6-second rolling audio window against the local enrolled voice before greeting. Rejected candidates do not awaken the assistant. Normal question audio is checked before sending either final or recovered provisional transcript to the assistant, when wake-triggered or standby mode is enabled. Manual microphone outside standby and typed input remain available. Very short questions may fail the full-question threshold; no authorization or anti-replay promise. Mixed speech, actual owner wake detection, and media/ambient false-accept rate still require live testing.
- No recorded audio files, uploaded audio, or printed embeddings. Local pipes and bounded RAM only, raw command audio discarded after take/cancel. Missing/invalid owner profile or model failure does not bypass standby filter. Enrollment data stays outside repo and bundle. The signed app includes only the gate script and local inference helper. Model loads per wake rearm and command verification; added latency must be measured in real use.
- Verified 301 Python tests (including source contracts), Swift debug build, bounded PCM conversion/take/discard test, real-model synthetic matched reference positive and different registered owner negative wake/command test, silence rejection. No live mic test by development.
