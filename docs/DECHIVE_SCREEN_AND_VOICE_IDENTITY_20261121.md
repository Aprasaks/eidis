# DECHIVE / Mac JARVIS identity contract
Date: 2026-11-21 (Asia/Seoul)

## 1. 확정된 정체성
- **보여 주는 모든 브랜드/UI 이름은 DECHIVE**.
- **사용자가 부르는 음성 이름은 자비스**. 음성 명령의 `자비스` 접두사 라우팅을 유지.
- **비서가 사용자에게 쓰는 호칭은 주인님**. 과거 저장된 `display_name`과 구별.
- DECHIVE는 서비스/앱 브랜드이며 사용자의 사람 이름이나 호칭이 아님.
- 개인정보/토큰/기존 DB/프로젝트 ID를 브랜딩만을 이유로 이름 변경하지 않음.

## 2. 지금 구현하는 범위
- Mac 앱 메뉴/윈도 제목/Info.plist 표시명, 홈/대시보드/LIVE DIALOGUE 등 사용자 화면 문구 DECHIVE로 교체.
- 오른쪽 LIVE DIALOGUE에서 체크박스, 슬라이더, 설정 설명, 별도의 버튼 제거. 실제 받아쓰기·확정 질문·비서 답변·상태만 보임. 화면 하단의 기존 마이크·Space 제어는 유지하여 사용자가 음성 대화를 중단할 수 있게 함.
- 기존 원본 JARVIS_FullHD_Loop.mp4를 보존한 채 별도 DECHIVE_FullHD_Loop.mp4 영상을 만들어 중앙의 JARVIS 글자를 DECHIVE로 대체. 1920x1080/10초 루프·금빛 코어의 영상 움직임 보존.
- macOS Keychain 식별자 `dev.dechive.eidis` 및 서비스 키는 절대 임의 변경하지 않음. 기존 Instagram·YouTube·ElevenLabs 접근성 유지.

## 3. '내 목소리 기억'은 별도 검증 대상
- 현재 있는 `JarvisVoiceCloneSetup`은 **사용자 음성을 합성 목소리의 참고로 사용하는 기능**으로, 동일인의 발화인지 확인하는 **화자 검증(speaker verification)** 기능과는 다르다.
- 현재의 `SFSpeechRecognizer`는 말한 한국어 내용을 전사하지만, 특정 사용자만의 목소리인지 보장하지 않는다. '주인님 음성만 자동으로 듣습니다'라고 표기하면 허위다.
- 이후 사용자가 동의하고 직접 시작하는 등록 과정: 서로 다른 문장으로 최소 복수 샘플 등록, 사용자에게 오인식/거부 가능성 명시, 기기 내부 암호화 저장, 비교 임계값·거부 조건 실측, 임베딩 삭제/재등록, 사용자 인증과 음성화자 판정 분리.
- 화면 잠금 해제, 광고비 결제, SNS 발행·삭제 같은 고위험 작업은 목소리 일치만으로 자동 실행하지 않음. 별도 확인 필수.
- 자비스 응답 중 자유롭게 말로 끼어드는 완전한 barge-in은 음성 출력 에코 제거 및 음성활동감지 실기기 시험이 선행되어야 함.

## 4. 미래 iPhone 앱 연동
- SwiftUI 관제 UI/명령 계약과 iOS용 화면을 공유할 가능성이 있지만, macOS의 `NSScreen`, 전체화면 패널, `AVAudioEngine`, 앱별 권한 설정을 그대로 iOS에 복사할 수는 없음.
- 우선 Mac에서 명령/결과의 데이터 모델과 비서 문맥을 분리하고, iOS는 마이크 권한/오디오 세션/백그라운드 제한과 모바일 인증을 별도로 검증.
- 동기화가 필요하다면 명시적으로 선택한 내용만, 권한이 다른 공개 API 토큰을 클라이언트 앱에 내장하지 않는 구조부터 설계.
- 이번 변경에서 iPhone 앱 배포 또는 사용자 화자 식별 완료를 주장하지 않음.

## 5. 직접 확인할 사항
- 실행 시 macOS 앱 이름 DECHIVE, 메뉴바 DECHIVE, 코어 영상의 글자 DECHIVE, 우측 패널 DECHIVE / LIVE DIALOGUE.
- 우측 패널에 설정/버튼/슬라이더가 없어야 하며 하단 음성 입력은 유지.
- 자비스라고 부르면 기존 인식이 유지, 새 음성 인사는 '주인님, 자비스입니다'.
- 전체 대시보드, YouTube, Instagram, GitHub, Vercel 등 실제 연결 값/토큰 상태 변화 없음.
- 음성 화자 식별과 iPhone 앱 연동은 현재 미구현.
