# JARVIS v2.2 — 프로젝트 확인 작업의 제안·승인·실행·결과

## 동작
- Mac 앱의 **작업** 탭에서 등록된 프로젝트와 마지막 확인 기록, 할 일 목록을 **로컬 서버**에서 읽습니다. 이때 GitHub에 접속하지 않습니다.
- 프로젝트 선택 → **읽기 전용 작업 제안 만들기**를 누르면 연결된 공개 GitHub 저장소의 HEAD/Workflow 확인 작업 한 가지를 제안합니다.
- 제안 범위(저장소, 읽는 데이터, 기록 여부, 금지 행위)를 사용자에게 표시합니다.
- **이 작업 승인 화면 열기 → 승인하고 공개 GitHub 1회 조회**를 사용자가 직접 눌러야 실제 외부 API 조회가 시작됩니다.
- 호출 직전 프로젝트 ID, 이름 및 저장소가 제안 당시 그대로인지 로컬 서버에서 다시 확인합니다.
- 기존 서버 도구 `github.public_verify`가 등록된 공개 저장소의 기본 브랜치 HEAD와 일치하는 Workflow 여부만 읽습니다. 승인한 프로젝트에 대한 실행 영수증 및 마지막 확인 기록을 기존 SQLite에 남깁니다.
- 결과 화면은 커밋, Workflow 상태, 확인 시각, 영수증 ID를 구분합니다. AWS 실제 배포 완료 여부로 오인하지 않습니다.
- 조회 한도는 서버 한 실행당 총 8회입니다. 실패·응답 불확실 시 자동 재시도하지 않습니다.

## 금지·개인정보
- 파일 수정, GitHub 푸시, 브랜치 병합, AWS 변경, 자동 배포, 작업 완료 자동 판단, 삭제·결제는 이 화면에 연결하지 않았습니다.
- GitHub 토큰이나 별도 LLM/API 키를 사용하지 않습니다. 공개 GitHub API에 조회 대상 공개 저장소 경로가 전달됩니다.
- 로컬 프로젝트 메모리 조회는 API 키 없이 `127.0.0.1:8765`로만 진행합니다.
- 승인 없이 외부 조회를 시작하지 않습니다. 페이지 진입/프로젝트 선택은 로컬 GET 요청만 실행합니다.
- 조회 실패나 네트워크 응답이 불분명해도 성공으로 표시하지 않고 재시도하지 않습니다.
- 실행 영수증은 서버 기록이며 실제 배포 또는 프로젝트 작업 완료 증거가 아닙니다.

## 검증
- SwiftUI macOS 실기기 빌드 성공.
- 실제 API 형식과 일치하는 모의 프로젝트 2개 JSON 디코딩 및 제안 생성/비연결 프로젝트 차단 테스트.
- 기존 Python 서버 테스트: 승인된 공개 GitHub 조회, 한도, 거절 및 provenance 검사.
- 실제 승인 버튼의 사람 클릭과 앱 UI 렌더링/네트워크 트래픽은 Mac 앱에서 직접 테스트해야 합니다.
