# JARVIS — 로컬 지식·기억 시스템의 방향 (2026-11-24)

> **상태: 사용자와의 대화에서 확정한 제품 방향 및 설계 원칙.**
> 이 문서는 구현 완료 보고서가 아니다. 기존 앱의 검증된 기능과 구현 예정 기능을 구분한다.
> 기존 문서·데이터베이스·앱 코드를 덮어쓰지 않는 별도 방향 문서이다.

## 우리가 만들려는 것

JARVIS는 단순한 음성 명령 앱이나 Apple Siri의 복제품이 아니다.
사용자와의 실제 대화, 뉴스, 일정, 프로젝트 수행과 그 결과를 **근거와 함께 로컬에 축적**하고,
그 기록을 이후 질문·판단·행동에 활용하는 개인 AI 지식 시스템이다.

- 기능의 양보다 **맥락의 연결**을 중요하게 생각한다.
- 어제보다 더 많은 기록이 쌓여도, 오늘 더 정확한 답을 할 수 있어야 의미가 있다.
- 무조건 저장하거나 AI가 추론한 것을 확정된 사용자 사실로 취급하지 않는다.
- 사용자가 잘못된 기억을 확인하고 **수정·삭제**할 수 있어야 한다.
- DECHIVE의 핵심 가치: **AI의 답은 검증이 시작**이다.

## 아침 루틴 — 사용자가 원하는 순서

1. iPhone JARVIS 자체 알람으로 기상.
2. 알람을 확인/종료하면 '애기'가 친근한 아침 인사를 한다.
3. 오늘의 뉴스 브리핑을 음성으로 듣는다.
4. 브리핑 이후 Mac ↔ iPhone 동기화된 JARVIS Calendar로 오늘 일정 및 준비사항을 안내한다.
5. 궁금하면 질문하고 설명을 더 듣고, 계속 듣기를 요청해 흐름을 이어갈 수 있는 것이 장기 목표다.

### 뉴스 편성 — 사용자와 합의한 기본값

- **한국 경제 뉴스 1건**: 금리·물가·증시·경제 정책과 실제 생활 영향.
- **한국 정치 뉴스 1건**: 국회·정부·법안·정책의 확인된 사실과 쟁점. 특정 정치적 견해를 단정하지 않는다.
- **글로벌 AI·기술 뉴스 1건**: 공식 발표·연구·오픈소스·실제 사용 가능성과 한계를 구분한다.
- 하루 기본 3건, 약 3분 내외의 이해하기 쉬운 전달을 지향한다. 수치는 초기 운영 가설이며 실사용 후 조정한다.
- 적합하거나 확인 가능한 기사가 없는 분야는 **억지로 채우지 않는다**.
- 기사는 '무슨 일이 있었는가 → 왜 중요한가 → 확인 가능한 영향/한계' 순서로 설명한다.
- 인기도·클릭 유도만으로 선정하지 않는다. 수집 출처·게시 시각·검증 수준·새로운 사실을 따진다.
- 기사 전문을 무단 복제하지 않는다. URL·출처·날짜·허용된 메타데이터와 자체 작성 결과를 구분해 저장한다.

## 핵심 데이터 구분

1. **News Source/Archive** — 기사/공식 자료의 URL, 출처, 공개·수집 시각, 언어·지역, 원본 제공 주장, 상태, 중복 판정.
2. **Verified Knowledge** — 확인된 사실, 근거, 검증 주체·시각, 검증 범위, 반대 근거, 정정 및 철회 이력.
3. **Morning Briefing** — 해당 날짜의 선정 기사, 왜 선정했는지, 읽은 대본, 음성 버전, 읽음/재생 위치 등 청취 이력.
4. **Personal Memory** — 사용자가 직접 말하고 승인한 선호·경험·일정·프로젝트와 실제 작업 결과.
5. **Assistant Inference** — AI가 추론한 관심사·가설은 어디까지나 추론으로 구분. 사용자 사실로 승격하지 않는다.

자료의 **출처, 생성 시각, 갱신 시각, 검증 상태, 수정 이력**을 보존한다.
예전에 맞았던 사실도 현재는 달라졌을 수 있으므로 최신성·근거를 다시 확인한다.
기억을 지웠다면 검색·요약·캐시 및 브리핑에서 재노출되지 않도록 데이터 경로를 설계한다.

## 로컬 AI의 '학습' 의미

- 1단계: **Memory + Knowledge DB + 검색/RAG + 로컬 LLM**이 관련 기록을 조회해 근거 있는 답을 만든다.
- 이는 모델 가중치가 자동 학습되는 것과 **다르다**. '기억 증가 = 모델 파인튜닝 완료'라고 주장하지 않는다.
- 파인튜닝은 필요성과 데이터셋·평가·동의가 확보될 경우에 별도 검토한다.
- 오류 정정의 용이성·삭제 가능성·출처 추적을 이유로, 변화하는 뉴스와 사용자 맥락은 DB 기반 검색을 우선한다.
- 비밀번호·인증 토큰·민감정보, 자동 프로필 추론을 무조건 저장하지 않는다.
- 외부 AI/TTS/API를 호출할 때는 비용과 원문/음성 데이터의 외부 전송 여부를 사용자에게 명확히 알린다.

## 구현 현황과 반드시 남겨둘 검증 경계

### 현시점 확인된 사항

- Mac ↔ iPhone JARVIS Calendar의 생성 및 동기화가 실기기에서 확인되었다.
- iPhone JARVIS AlarmKit 자체 알람이 **실제 울린 것**을 사용자가 확인했다.
- Mac에는 RSS 기반 뉴스 수집과 SQLite `morning_briefings` 테이블을 사용하는 브리핑 잡 구조가 존재한다.
- 2026-11-24 수집 실험: 6개 RSS 중 4개 읽기 성공, 7개 기사 선별; 출처 일부 조회 실패.
- 현재 브리핑 저장 테이블의 실제 내역 0건을 확인했다(2026-11-24 확인 시점).
- JARVIS iPhone v0.4.1 빌드10에 '일어났어' 보조 버튼용 App Intent를 추가·설치했으나 **버튼 표시/기상 확인 동작 자체의 실기기 성공은 아직 확인 전**이다.

### 아직 완료하지 않은 항목

- 한국 정치에 적합한 검증 가능한 소스 보강 및 뉴스 수집 안정성 개선.
- 기사 단위 아카이브와 정정 가능 검증 기록, 날짜별 고정 브리핑, 재생 위치 기록.
- iPhone 뉴스 UI·음성 재생과 Mac 뉴스 저장소 사이의 실데이터 연결.
- 잠금 화면에서 '일어났어' 버튼을 눌렀을 때 아침인사로 이어지는 iOS 승인 가능 흐름.
- 뉴스 → 오늘 일정 → 관련 프로젝트/준비사항으로 이어지는 맥락 기반 브리핑.
- 개인 대화·뉴스를 모두 자동으로 안전하게 장기 기억하는 기능 및 RAG 정확도 실기기 평가.

## 개발 순서와 검증 게이트

1. **뉴스 수집의 신뢰성**: 한국 경제·정치 및 글로벌 AI·기술 소스별 안정성/최근 24시간 검증; 실패는 명시.
2. **영구 보존**: 뉴스 아카이브/브리핑 스냅샷/청취 상태를 기존 로컬 SQLite에 비파괴적으로 추가. 사용자가 원하는 경우 삭제·정정 가능하게 구현.
3. **읽을 수 있는 결과**: 먼저 Mac/iPhone에 세 가지 소식과 각각의 출처·검증 상태를 표시; 기사 선정 로그를 남긴다.
4. **음성화**: 실제 TTS 경로로 브리핑 낭독·일시정지·계속 듣기·반복 청취 검증. 인터넷/서비스 장애 시 실패 고지.
5. **알람 연계**: '일어났어' 실기기 동작 확인 → 사용자 승인 기반 아침인사 → 뉴스 브리핑; iOS 잠금/백그라운드 제약을 우회하거나 성공을 허위 표시하지 않는다.
6. **일정·기억 연결**: 검증된 실제 캘린더/프로젝트/기억을 참조해 당일 준비사항을 설명한다. 데이터가 없으면 추측하지 않는다.
7. **기억 품질**: 관심사 피드백, 정정, 출처 추적, 검색 품질 평가, 중복 제거, 정보 노후화 정책 추가.

각 단계는 **소스 구현 → 자동 테스트 → 실제 데이터 확인 → Mac/iPhone 실기기 검증**을 구분해 보고한다.
테스트용 가짜 기사를 실제 뉴스로 저장하거나, 확인하지 않은 기능을 '완료'로 표시하지 않는다.

## 변경 원칙

- 기존 JARVIS Mac 금빛 코어, iPhone UI, Calendar 데이터, 사용자가 저장한 기록과 계정 연결을 보존한다.
- 구현 시 필요한 부분만 수정하고, 사용자 승인 없이 기존 데이터/설정을 초기화하지 않는다.
- 작업 이후 무엇이 **작동/검증/미구현**인지 항상 구분한다.

## 북극성

**'매일 뉴스를 읽는 앱'이 아니라, 사용자의 시간과 경험에 근거하여 지식이 축적되고,
그 근거가 검증·정정되며, 다음 날 더 유용하게 도움을 주는 로컬 JARVIS.**
