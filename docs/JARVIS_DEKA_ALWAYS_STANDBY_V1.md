# DEKA session-long standby — experimental
- Explicit menu opt-in: 데카 상시 대기 켜기 / 끄기. No automatic startup capture or persisted wake opt-in. The existing mini core remains visible when closing fullscreen. No change to visual layouts or the classifier threshold/model.
- The 3-minute capture limit is removed. Worker startup still has a 15-second bound. Each detected wake stops and releases the standby microphone before the local greeting; the existing Korean speech recognition then captures one question. Both mini and fullscreen use single-turn capture while opted in. After playback, the monitor re-arms following a short cooldown. No simultaneous standby and command recognition. During greeting, thinking, speaking, or active output the wake detector is paused.
- Standby stops on menu disable, settings opening, sleep, app termination, hiding the final core, or model/audio errors. Sleep/relaunch requires explicit opt-in again. Turning standby off does not cancel an already started ordinary conversation; use Esc/voice controls for that. No audio recording or network transfer from wake capture.
- 298 automated Python tests (including source-contract checks), Swift build, synthetic 190 seconds of silence then a DEKA clip (accelerated, not elapsed microphone time), three independently restarted worker cycles, synthetic PCM relay conversion. Actual repeated live calls, wake-to-greeting latency, prolonged idle CPU and false alarm rate are unverified. Earlier real voice test 2/4 hits and 0/4 noncalls; this change does not improve classifier accuracy.
