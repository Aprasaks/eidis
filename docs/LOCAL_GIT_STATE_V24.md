# JARVIS v2.4 — Mac 로컬 Git 코드 상태 확인

## 실제 사용 방법
1. Mac **JARVIS → 작업** 탭에서 프로젝트를 선택합니다.
2. **Mac 코드 상태**에서 **Git 폴더 연결**을 누릅니다.
3. macOS 폴더 선택 창에서 직접 Git 저장소 폴더를 선택합니다. 연결된 경로는 Mac의 앱 설정(UserDefaults)에 프로젝트별로 저장하며, 서버·SQLite·GitHub에는 전송하지 않습니다.
4. 그 자리에서 한 번 상태를 읽고 브랜치, 로컬 HEAD, 추적된 변경 항목 수, 미추적 항목 수와 확인 시각을 보여줍니다.
5. 이후 **현재 코드 상태 한 번 확인**을 눌러야 새로 검사합니다. 앱 시작·프로젝트 변경만으로 Git 검사를 실행하지 않습니다.
6. **연결 해제**를 누르면 저장된 경로와 마지막 확인 결과를 앱에서 지웁니다. 실제 Git 저장소는 그대로 남습니다.

## 읽는 정보와 제한
- 실행 파일은 /usr/bin/git로 고정했습니다. 셸 스크립트나 사용자가 입력한 명령 문자열을 실행하지 않습니다.
- 허용하는 Git 명령은 `rev-parse --show-toplevel`, `rev-parse --abbrev-ref HEAD`, `rev-parse --verify HEAD`, `status --porcelain=v1 -z --untracked-files=normal --no-renames`입니다.
- Git에는 `--no-optional-locks`와 `-c core.fsmonitor=false`를 적용하여 선택적 인덱스 업데이트와 fsmonitor 호출을 막습니다.
- 상태 응답의 파일명·파일 내용은 UI에 표시하지 않고, 변경 항목 수만 셉니다. Git status의 미추적 항목은 디렉터리 단위로 묶일 수 있으므로 **미추적 파일의 정확한 수가 아니라 항목 수**입니다.
- Git 응답을 최대 512KiB, 각 명령 최대 약 8초로 제한합니다.
- 로컬 브랜치와 원격 GitHub 브랜치가 같아 보이더라도 동기화·배포 완료라고 단정하지 않습니다. 실제 최신 상태는 클릭했을 때 본 로컬 스냅샷 기준입니다.
- Git 저장소의 설정에 따라 내부적인 읽기 처리 비용이 발생할 수 있으며, 권한이나 파일 손상으로 조회가 실패할 수도 있습니다. 실패 시 이전 결과를 최신 결과로 남기지 않습니다.
- 원격 네트워크 요청, git push/commit/checkout/reset/clean, 코드 생성·변경, 자동 동기화, AWS 배포는 하지 않습니다.

## 검증 범위
- 실제 Mac의 JARVIS 저장소에서 로컬 Git 브랜치/HEAD/변경 항목 수를 subprocess로 읽는 스모크 테스트를 통과했습니다.
- NUL 구분 Git 상태 결과와 잘못된 형식을 구분하는 테스트가 통과했습니다.
- 전체 Swift 앱 빌드, Python 계약 테스트와 로컬 앱 설치를 확인했습니다.
- 실제 사용자가 폴더 선택 창을 열고 앱에서 선택하는 GUI 상호작용은 별도 실사용 검증 대상입니다.
