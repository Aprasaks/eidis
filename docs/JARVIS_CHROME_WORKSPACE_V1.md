# JARVIS Chrome 작업 공간 — 2026-11-22

SNS 열기 요청 시 기존 JARVIS 화면/대화 객체를 종료하던 경로를 폐기했다. 기존 로그인 Chrome을 사용하는 전용 창을 오른쪽에 배치하고, 동일 JARVIS 패널을 왼쪽 코어/대화 공간으로 전환한다. 실제 Chrome 창이며 SwiftUI WebView 임베딩이 아니다. Chrome 쿠키, 비밀번호, 저장소는 읽거나 복사하지 않는다. Chrome 창 배치에는 macOS 자동화 권한이 필요할 수 있으며 실패 시 기존 패널을 유지하고 오류를 표시한다.

- 기존 사용자의 다른 Chrome 창을 변경하지 않고 전용 창을 만든다. 같은 JARVIS 세션에서 전용 창의 동일 공식 채널 탭이 있으면 선택하고 없으면 새 탭을 추가한다.
- 코어, 대화 기록, 음성 처리 객체를 유지한다. 오른쪽 브라우저가 키보드 포커스를 가질 때 Escape의 전역 가로채기를 해제한다.
- 전체 현황 버튼 및 Command-Option-J로 기존 관제실로 복귀한다. Chrome 창은 그대로 유지하며 JARVIS는 종료하지 않는다.
- 설치된 앱의 Instagram 카드 클릭 시 실제 화면에서 JARVIS 470x1050, Chrome 1442x1050, 사이 8pt 분리가 확인되었다. 사이드바 실화면에서 코어/대화/전체 현황 버튼 표시 확인. 전체 현황 버튼으로 동일 앱 PID의 관제실 복귀 확인. 실제 음성 발화 및 다른 SNS 브라우저 로그인은 별도 검증 대상이다.
- Swift 빌드 및 Python 테스트 325건 통과. 기존 Chrome MCP 연결 도구와 공식 API 계정 연결 유지.
