# JARVIS v3.14.1 — 반응형 전체 현황 관제실

## 사용자 요청과 구현

- `자비스, 전체 현황 보여줘`, `관제실 보여줘`, `전체 대시보드 띄워줘` → 원래 중앙 금빛 코어 영상이 끊기지 않고 왼쪽 상단으로 이동하면서 **JARVIS / COMMAND CENTER** 전체 화면으로 전환한다.
- 본래 영상 `JARVIS_FullHD_Loop.mp4`는 편집/교체하지 않는다. 원래 `AVPlayerLooper` 한 개를 재사용하여 화면 모드에 따라 AVPlayerLayer의 크기와 `.resizeAspectFill` 크롭만 전환한다. 0.72초 이동 애니메이션 및 접근성 '동작 줄이기' 옵션 지원.
- 화면 비율이 넓으면 왼쪽에 회전 코어+실제 체크 로그, 오른쪽에 프로젝트·로컬 Git·YouTube·자료 보관함·시스템·JARVIS 이벤트 로그가 배치된다. 논리 폭이 1120pt보다 작으면 아래로 이어지는 수직 레이아웃으로 조정한다. 스크롤하며 더 많은 항목을 볼 수 있다.
- 글자 크기는 화면 논리 크기에 맞춰 최대 2.2배까지 조정. 16:9 TV용 화면도 동일한 GeometryReader 레이아웃을 사용하도록 작성. **실제 TV 연결 실기기 검증은 아직 수행하지 않았으며**, Mac 내장 화면에서만 전체 UI를 직접 촬영하고 확인했다.
- `원래대로 돌아가`, `관제실 닫아` → 대시보드만 숨기고 코어를 다시 중앙에 놓는 로컬 명령 경로가 추가되었다. 명령 파서와 로컬 대시보드 숨김은 런타임에서 검증했다. 최종 실제 음성 복귀 명령은 마이크 인식 정확도까지 포함해 별도 검증이 필요하다.
- `Esc`는 작업 중이라도 전체 화면을 즉시 닫는다. 앱 백그라운드 프로세스와 로컬 메모리 DB는 유지.

## 연결한 실데이터와 출처

- **프로젝트/작업**: JARVIS 127.0.0.1:8765의 `/api/projects`; 실제 프로젝트 2개, 작업 25건(기존 기록 그대로).
- **로컬 Git**: macOS `/usr/bin/git`을 사용해 `~/Documents`, `~/Developer`, `~/Projects`, `~/Code`가 존재하는 범위 내에서만 파일시스템을 제한 탐색. 현재 Mac에서 14개 로컬 저장소 발견. 브랜치·마지막 커밋·추적 중인 파일 변경 수를 읽는다. GitHub 원격 계정 전체 저장소나 동기화 정보가 **아님**. 읽기 전용이고 `git fetch/push/checkout` 등 네트워크·변경 명령을 실행하지 않는다. 탐색 최대 디렉터리 1200개, 깊이 3, 저장소 35개 제한; 탐색 한도 도달 시 경고.
- **지식 보관함**: `/api/vault?limit=12`, 활성 자료 및 분류별 건수. 테스트 자료는 archive되어 현재 활성 0건.
- **시스템 상태**: `/api/diagnostics`, `/api/status` 및 로컬 Ollama `/api/version`; 실제 연결 결과만 노출.
- **LIVE CHECKS**: 실제 HTTP 조회 결과/로컬 Git 읽기 결과의 성공·실패 시각과 수치만 기록하고, 7초 간격으로 조회할 때 최대 40개 항목을 순환 표시. 의미 없는 가상 작업 로그를 생성하지 않는다.
- **RECORDED EVENTS**: `/api/activity`의 기존 실제 작업 이벤트 기록에서 시간/분류/결과를 표시. 기록 시각은 과거 값 그대로 표시하므로 오늘 발생했다고 오해하지 않도록 설명.
- **YouTube**: 계정 API 미연결 상태. 채널 조회수·구독자·영상 성과를 만들어내지 않고 `API NOT CONNECTED` 표기.

## 검증 · 2026-11-20 (Mac)

- 연결이 잠시 끊겼으나 Remote Desktop Commander를 재연결하고 기기 명령을 다시 실행하여 소스 수정/빌드/설치를 완료.
- Swift 빌드 성공; Python 자동 회귀 테스트 **185개 통과**; 앱 서명은 기존 Apple Development의 안정적인 designated requirement 유지.
- 별도 Swift 런타임 테스트: '전체 현황/관제실/원래대로' 등 자연어 의도, 실제 프로젝트 2개·작업 25건, 저장 자료, 기록 이벤트, Ollama 응답, 로컬 Git 14개, 7초 뒤 갱신 시각 증가, 숨김 뒤 갱신 정지 확인.
- macOS 내장 디스플레이 1512×982 논리 pt(3024×1964 물리 px)에서 실제 전체 화면 `전체 현황 보여줘` → 코어 왼쪽 이동과 프로젝트/Git/YouTube/자료/시스템/이벤트 패널 표시를 스크린샷으로 확인 (v3.14.0 시각 테스트).
- 해당 화면에서 1.3초 간격으로 두 번 캡처한 **왼쪽 코어 영역**의 SSIM 0.807로 서로 다른 실제 영상 프레임 확인(단순 정지 이미지 아님).
- v3.14.1에서 큰 화면용 글자 배율 보정, 일반 화면과 관제실의 중복 닫기 버튼 방지, 원본 영상 하단 JARVIS 자막의 희미한 잔상 페이드 조정. 같은 코드와 자산으로 최종 Swift 빌드/자동 테스트 통과 및 앱 교체 설치. 최종 v3.14.1에 대한 별도 전체 화면 스크린샷 검증은 진행 중 UI 음성 자동 인식으로 인한 불안정한 자동화 때문에 미완료. UI 제어 문제를 앱 정상 기능 문제로 단정하지 않음.
- `Esc` 실제 입력: 오버레이 창 0개, 앱 프로세스/로컬 서버 유지, SQLite 진단 `ok`. 키체인 암호 팝업 없음.
- 사용자 프로필 8건(호칭 데카이브), 프로젝트 2개 및 작업 25건 그대로. 기존 v3.13.1/v3.14.0 앱 백업 보존.

## 현재 남은 작업과 한계

- 실제 HDMI/Apple TV/AirPlay 등 외부 TV 연결 후 1920×1080, 3840×2160에서 UI 가독성·오버레이 위치·기기 간 이동을 실기기로 검증. 이번에 연결된 화면은 Mac 내장 디스플레이 한 대뿐.
- 현재 상호작용은 로컬 텍스트 및 명시적 마이크 호출 기준. 별도의 항상 듣는 깨우기 말 `자비스`는 구현하지 않음.
- YouTube/GitHub 원격 계정/Notion/외부 리서치 API 연결과 외부 갱신 수치는 향후 별도 작업. 가짜 값이나 출처는 사용하지 않음.
- 자동 음성 인식이 배경 소음을 받아 예기치 않은 발화로 이어질 수 있으므로, 실기기 음성 명령은 소음 통제 하에서 사용자와 별도로 확인할 것.
