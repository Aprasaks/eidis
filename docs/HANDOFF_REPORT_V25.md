# JARVIS v2.5 — 프로젝트 인수인계 요약

## 목적
자비스를 다시 열었을 때 이전 프로젝트에서 어디까지 기록했는지, 무슨 일이 남았고 무엇을 실제로 확인했는지 한눈에 확인합니다.

## 실제 사용
1. Mac JARVIS 앱의 **작업** 탭을 열고 프로젝트를 선택합니다.
2. 화면 상단 **프로젝트 인수인계 · 저장된 사실과 미확인 항목**에서 프로젝트 목표, 예정·진행·막힘·완료 작업 수, 다음에 이어 할 일(진행→예정), 막힌 작업을 확인합니다.
3. **Mac 로컬 Git** 섹션에는 사용자가 이전에 직접 눌러 읽은 브랜치·HEAD·변경 항목 수와 **확인 시각**을 표시합니다. 폴더만 연결하고 아직 조회하지 않았다면 확인 미실시로 표시합니다.
4. **공개 GitHub** 섹션에는 사용자가 마지막으로 승인한 GitHub 확인 기록의 기본 브랜치·HEAD·Workflow 상태·확인 시각을 표시합니다. 기록이 없으면 조회하지 않았다고 표시합니다.
5. **인수인계 내용 복사**를 클릭하면 이 요약 문자열을 사용자의 클립보드에 복사할 수 있습니다. 복사에는 작업 제목과 목표가 포함될 수 있으므로 공유 전 확인하세요.

## 증거 구분
- 사용자 작업 기록은 개발 완료·테스트 통과·실제 배포 성공의 증거가 아닙니다.
- GitHub의 과거 HEAD 기록은 현재 원격 최신 상태가 아닙니다. AWS 배포 성공 여부도 확인하지 않습니다.
- Mac Git 스냅샷은 확인 버튼을 눌렀을 당시의 결과입니다. 앱 시작이나 인수인계 보고서 생성 시 자동 재검사하지 않습니다.
- Mac 폴더가 프로젝트와 연결된 GitHub 저장소와 동일한지 자동으로 확인하지 않습니다.
- 인수인계 문서에는 개인 Mac의 절대 파일 경로를 포함하지 않습니다.
- 인수인계는 로컬에서 이미 로드한 데이터로 문자열을 조립할 뿐, 신규 파일 쓰기·자동 커밋·GitHub/AWS API 호출을 하지 않습니다.

## 확인한 테스트
- Swift 앱 빌드 성공.
- Swift 합성 데이터에서: 작업이 없는 경우/진행·예정·막힘이 있는 경우, 로컬 Git 스냅샷이 있는 경우/없는 경우, GitHub Workflow 불명확, 절대 경로 미포함을 검사.
- Python 계약 테스트로 읽기 전용 변환 및 명시적 클립보드 버튼 검증.
- 실제 Mac UI에서 요약 표시·복사 결과는 사용자가 앱을 조작해 확인해야 합니다. 이 코드 테스트만으로 실사용 성공을 선언하지 않습니다.
