# JARVIS v3.4 — 한국어 음성 명령 녹음 종료 안정화

## 해결하려는 문제
이전 음성 탭은 사용자가 **완료하고 명령 전달**을 누르면 오디오 종료와 동시에 음성 인식 작업을 즉시 취소했습니다. 이 때문에 문장 끝부분이 확정되기 전에 끊길 수 있었습니다. 이는 코드상 잠재 원인으로 확인한 것이며, 실제 사용자의 마이크에서 그 현상이 발생했다는 진단은 아직 없습니다.

## 바뀐 동작
1. Mac 앱 **음성 → 마이크로 말하기**를 누르면 **한국어 온디바이스 인식** 지원 및 마이크·음성 인식 권한을 확인합니다. 승인 요청은 사용자가 직접 처리해야 합니다.
2. 말하는 동안 인식 문장이 화면에 보입니다. 추천 실습 문장: **자비스, 다음 할 일 뭐야?**
3. **완료하고 명령 전달**을 누르면 녹음 탭을 먼저 제거하고, 오디오 요청을 종료한 뒤, 음성 인식의 최종 결과를 최대 **1.5초** 기다립니다.
4. 최종 결과가 오면 **최종 전사**, 그렇지 않고 마지막 인식 문자열만 있으면 **마지막 임시 전사**라고 표시합니다. 둘은 같은 검증 수준이 아닙니다.
5. 인식 오류·취소·빈 문장은 **서버에 전달하지 않습니다**. 문장이 있으면 기존 로컬 자비스 명령 처리기로 한 번 전달합니다.
6. 앱의 **자비스 응답**에서 실제 로컬 서버 답변을 확인합니다. 답변이 읽혔는지는 사용자가 직접 들어야 확인할 수 있습니다. ElevenLabs가 비활성화되어 있으면 Mac 기본 음성 합성을 사용합니다.

## 안전·한계
- 배경에서 계속 듣는 기능이 아닙니다. 마이크 시작과 명령 전달은 각각 직접 버튼 조작이 필요합니다.
- 기기 내 한국어 음성 인식이 지원되지 않으면 외부 음성 인식으로 자동 전환하지 않습니다.
- 취소·새 세션에서는 이전 음성 인식 콜백을 무시합니다. 권한 승인 중 취소해도 오래된 시도가 새 시도에 영향을 주지 않도록 세션을 확인합니다.
- 실제 하드웨어 음성 입력과 TCC 권한은 자동 테스트에 포함하지 않았습니다. 사용자 앱에서 직접 발화해야 검증됩니다.
- 마지막 임시 전사는 음성 인식 최종 확정본이 아닙니다. 민감한 명령은 인식 문구를 확인한 뒤 수동 입력을 사용하는 것이 안전합니다.
- 명령 전송 시 기본적으로 `remote_consent=false`를 유지합니다. 기존 별도 승인 없이는 작업 공간 열기, 파일 수정, 배포를 자동 허용하지 않습니다.

## 검증
- 컴파일·네이티브 UI 스모크와 Python 동작 경계 계약 테스트
- Swift 순수 의사결정 테스트: 문장 공백 제거, 빈 문장/오류의 전송 차단, 최종·임시 전사 구분
- Mac localhost 텍스트 명령 왕복은 v3.3에서 이미 실제 검증되었으나, 이번 변경의 **마이크 음성 입력 자체**를 검증한 것은 아닙니다.

## Mac 실사용에서 확인할 순서
**진단** 탭에서 마이크·음성 인식 권한을 확인 → **음성 → 마이크로 말하기** → 문장 발화 → **완료하고 명령 전달** → 최종/임시 인식 표시와 **자비스 응답** 확인 → 한국어 TTS가 실제로 들렸는지 사용자 확인.

실패한다면 권한 표시, **인식한 문장**, 화면에 표시된 오류 문자열 세 가지를 확인하면 어느 단계가 막혔는지 구분할 수 있습니다.
