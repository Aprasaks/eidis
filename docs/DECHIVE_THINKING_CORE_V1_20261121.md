# DECHIVE THINKING CORE 1.0 — 구현 및 검증 기록

## 목적
주인님이 별도 모드/버튼 없이 자연스럽게 말하면, 기존 빠른 명령 흐름을 유지하면서 필요한 경우에만 과거 기록과 프로젝트 상황을 Qwen3.5 대화에 연결한다. 이전 AI 판단을 임의로 사실화하거나, 비용이 드는 외부 API를 호출하지 않는다.

## 이번에 연결한 실제 범위
- `JarvisThinkingRoute` (Mac, 로컬): 사용자의 문장으로 빠른 대화/맥락 대화/검토 대화를 분류한다. 추가 AI 호출 없음, 버튼 없음.
- `/api/thinking/context` (Mac 내 Python, loopback only): 사용자가 명시적으로 저장한 메모, 보관함 자료, 로컬 프로젝트와 작업, 사용자가 별도로 저장 승인한 사고 기록 가운데 관련성 점수가 있는 상위 5개만 검색한다. 반환할 때 출처 ID, 시점, source_status 유지. 검색은 읽기 전용.
- `JarvisThinkingCore.context` (Swift): 맥락이 필요할 때만 짧은 로컬 요청(2초 요청 제한, 2.5초 전체 자원 제한). 실패하면 기존 Qwen 대화로 안전하게 복귀하며, 없는 기억을 만들어내지 않도록 안내한다.
- 일반 Ollama 요청에서 `num_ctx`는 fast=4096, contextual/deliberate=6144, `num_predict`는 deliberate=380, else=260. 24GB Mac에서 실측 후 조정할 수 있다.
- 현 단계에서 `think: false` 유지. 직접 수행한 짧은 모델 검증에서 fast(false)는 6.31초/답변 113자, forced thinking(true, num_predict=145)은 3.9초/최종 본문 0자로 확인됨. 이 결과는 동일 크기 작업 비교가 아니므로 속도 우위 근거로 쓰지 않고, **답변이 없을 수 있다는 호환성 경고**로만 사용.
- `thought_records` SQLite 테이블만 추가. 기존 개인 프로필, 저장 메모, 보관함, 프로젝트 테이블의 내용을 변경하지 않음. 시점과 가설 출처를 저장하며 `hypothesis` / `user_reviewed` / `rejected` 상태만 허용. 사용자 검토가 사실 검증 완료를 의미하지 않음.
- 사용자가 명시적으로 `방금 생각 기록해줘`라고 말할 때만 직전 모델 답변을 가설로 저장한다. `사고 기록 보여줘`로 최근 기록 조회. `3번 생각 틀렸어`로 상태를 거절/폐기, `3번 판단 검토했어`로 사용자 검토를 표시. 기존 기록의 과거 텍스트는 남겨두며 상태와 근거만 변경.
- 기존 DECHIVE 코어 영상/화면/호칭(주인님)/음성(자비스)/대시보드/Keychain/마이크 설정 코드는 변경 없음.
- 저장/검토 API는 현재와 동일한 `Host`, `Origin` 검사를 거치는 loopback-only 라우트. 개인 기록은 외부 API로 보내지 않음.

## 프라이버시·검증
- 원본 음성, 대화 전문, AI 추정 개인 정보를 자동 저장하지 않는다.
- 기존 자료가 없을 때 인식 결과를 '기억'이라 주장하지 않는다.
- 다른 사람의 음성인지 식별하는 기능, 무인 광고 집행/자동 SNS 게시, 자동 장기 사고 재실행, iPhone 동기화는 이번 버전에 포함하지 않는다.
- 기억에서 가져온 웹 원문과 AI 출력에 시스템 명령을 따르지 말라고 모델에 지시하지만, 로컬 9B 모델이 지시를 완벽하게 구분한다는 보장은 없다. 외부 콘텐츠에서 작업 실행을 허용하는 기능은 추가하지 않는다.
- **지속 가능성:** 독립 SQLite 백업, 추가 테이블만 사용하는 마이그레이션, 기존 앱 복사 백업, Git 커밋. 개인 DB는 Git이나 앱 패키지에 포함하지 않는다.

## 검증 절차
1. Git 깨끗한 상태와 실제 데이터의 복구용 SQLite 백업 확보 (개인 데이터는 출력하지 않음).
2. Python 메모리/프로젝트/보관함/사고 기록의 재조회·재시작·상태 전환·비밀키 문자열 거부 테스트.
3. 임시 로컬 HTTP 서버로 맥락 검색 및 외부 출처 쓰기 거부 테스트.
4. Swift 자연어 모드 분기와 음성 명령 구문 인식 스모크 테스트.
5. 기존 전체 Python 회귀 테스트, Swift 빌드, 앱 코드서명 검증, 패키징 검증.
6. 실제 Mac에 설치 후 로컬 서버 응답과 DB quick_check, 앱 프로세스, API 동작 확인.

## 현재 확인된 수치
- 전체 Python 회귀 검사: **224 tests / OK**.
- 추가 Swift 스모크 테스트: 빠른 명령 / 맥락 질문 / 분석 질문 / 명시적 가설 저장 / 사용자 정정 구문 모두 통과.
- 텍스트 검색 자체의 평균 수행시간: 가상 메모 100건에서 100회 평균 **0.159ms**. Mac 로컬 SQLite 기준이므로 마이크→답변 전체 시간을 뜻하지 않음.
- 동일 질문을 써서 Qwen 텍스트 출력만 한 번씩 시험했을 때: fast 7.268초(160자), contextual 4.285초(38자). **출력 길이가 달라 속도 향상 근거가 아니며**, 실사용 평균과 95백분위 응답시간은 추후 실제 측정해야 함.
- 설치 후 `/api/thoughts`와 `/api/thinking/context`가 실제 Mac 서버에서 정상 응답함. 보관된 사용자 자료를 변경하지 않고 프로젝트 유형 1건을 읽었음.
- 실 DB quick_check=ok, 기존 프로필 8건·프로젝트 2건·작업 25건·보관함 2건·메모 0건 유지. 사고 기록 0건부터 시작함.

## 실제 Mac 음성에서 추가 검증이 필요한 항목
- 주인님 발화: '자비스, 우리 취업 준비는 어떻게 생각해?' → 저장된 근거가 있을 때만 참고.
- '자비스, 방금 생각 기록해줘' → 사고 기록이 실제로 1건 증가하는지.
- '자비스, 사고 기록 보여줘' → 상태와 주제가 맞는지.
- '자비스, 1번 생각 틀렸어. 이유는 ...' → 사용자 입력으로 지정 기록이 rejected로 변경되는지.
- '자비스, 유튜브 열어줘' → 기존 명령이 여전히 불필요한 장기 검색 없이 처리되는지.
- 실제 음성 응답 시간과 검색 품질은 실기기 확인 전 **미검증**으로 남긴다.
