# JARVIS v2.9 — 저장된 다음 할 일에서 실제 작업 시작

## 사용 방법
1. JARVIS Mac 앱 **작업** 탭에서 프로젝트를 선택합니다. JARVIS eidis 자체 프로젝트로 먼저 시험할 수 있습니다.
2. **다음 할 일 시작**에서 최근 등록된 진행·예정 작업을 확인합니다. 진행 중인 작업을 먼저 보여주고, 같은 상태 안에서는 최근 등록 순서입니다. 자동 우선순위 판단이 아닙니다.
3. **예정** 작업에 대해 **이 작업 시작 제안 → 시작 승인 화면 → 승인하고 이 작업 시작 기록**을 누릅니다.
4. 승인한 **해당 1개 작업**에 대해서만 로컬 SQLite의 상태가 **예정(todo) → 진행(doing)**으로 변경되고, 서버 응답의 프로젝트·작업 ID·제목·새 상태를 확인해 화면에 반영합니다.
5. 상태 기록이 성공하면 같은 프로젝트의 **작업 이어하기**에서 Finder/GitHub 열기 **제안만** 생성됩니다. 실제 외부 앱을 열려면 기존 **열기 작업 1회 승인 화면**에서 다시 승인해야 합니다.
6. 이미 진행 상태인 작업은 **작업 공간 열기 제안** 버튼을 눌러 작업 환경 열기 제안만 만들 수 있습니다. 상태 기록은 변경하지 않습니다.

## 안전·정확성
- 제안 자체는 파일·코드·DB를 변경하지 않습니다. 제안의 유효기간은 2분입니다.
- 쓰기 전에 로컬 API GET /api/projects로 프로젝트 ID/이름/등록 저장소와 작업 ID/제목 및 **기존 예정 상태**를 다시 확인합니다.
- 프로젝트나 작업이 승인 이후 바뀌었으면 시작을 차단합니다.
- 승인 후 POST /api/projects/status 1회만 요청하며, 응답에서도 동일 프로젝트·작업 ID/제목과 **진행 상태**를 검사합니다. 결과가 불확실하면 **자동 재시도하지 않습니다**.
- 작업 기록의 진행 표시는 작업 수행·실제 코드 수정·커밋·GitHub Actions 성공·AWS 배포 완료를 의미하지 않습니다.
- 외부 LLM·GitHub·AWS를 자동으로 호출하지 않습니다. Finder/브라우저 열기는 별도 사용자 승인이 필요합니다.
- 기존 Python 서버의 상태 변경 API와 SQLite 이력을 재사용하며 새 마이그레이션은 필요하지 않습니다.

## 검증
- Swift fixture 테스트: 최근 작업 순서, 예정 작업 제안 생성, 진행·막힘·등록되지 않은 작업 차단
- Python 계약 검사: 명시적 승인, 서버 최신 상태 재확인, 결과 검증, 자동 재시도 금지
- 로컬 DB 상태 변경과 이력의 실제 동작은 기존 임시 SQLite 서버 통합 테스트에서도 검사
- macOS 앱 빌드와 사용자의 실제 버튼·권한 테스트는 각각 별도 확인
