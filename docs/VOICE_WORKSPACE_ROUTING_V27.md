# JARVIS v2.7 — 음성·텍스트에서 프로젝트 작업 이어하기

## 동작
1. Mac JARVIS 앱의 **음성** 탭으로 이동합니다.
2. 마이크 권한이 허용돼 있다면 **마이크로 말하기 → 완료하고 명령 전달**, 아니면 하단 텍스트 명령 입력창을 사용합니다.
3. 예시:
   - "DECHIVE.WIKI 작업 이어서 열어줘"
   - "DECHIVE.WIKI 깃허브 열어줘"
   - "JARVIS eidis 폴더 열어줘"
4. 등록된 프로젝트의 **정확한 전체 이름**과 작업 공간 열기 의도가 모두 확인되면, **작업** 탭으로 이동하여 해당 프로젝트의 Finder/GitHub 열기 **제안만** 만듭니다. 파일을 열지 않습니다.
5. 작업 탭에서 대상 경로·URL과 범위를 확인하고 **열기 작업 1회 승인 화면** → **승인하고 선택한 작업 공간 1회 열기**를 직접 눌러야 OS에 열기 요청을 보냅니다. 취소하면 실행하지 않습니다.

## 해석 제한
- 자연어를 이해하는 LLM이 아닙니다. 일반적인 문장 전체 분석은 하지 않으며, 지정된 키워드와 프로젝트명만 엄격히 비교합니다.
- "이어서 열어줘"는 연결된 Mac Git 폴더가 있으면 해당 폴더를 우선 제안합니다. 폴더 연결이 없으면 정확한 등록 GitHub 저장소 페이지를 제안합니다. 둘 다 없으면 실행할 대상이 없다고 표시합니다.
- 프로젝트명을 확인할 수 없거나 두 프로젝트명이 겹쳐 구별할 수 없으면 **임의로 선택하지 않습니다**.
- 배포·삭제·커밋·푸시·결제·발행을 열기와 함께 요청하면 열기 제안으로 처리하지 않습니다. 다른 명령이 자동 실행되는 일도 없습니다.
- 일반적인 질문은 기존 로컬 자비스 대화로 그대로 전달됩니다.
- 음성 인식은 Mac의 지원 상태와 사용자의 직접 허용에 좌우됩니다. 이 기능 추가만으로 실제 마이크/음성 인식 성공이 확인된 것은 아닙니다. 텍스트 입력은 마이크 권한이 없어도 사용할 수 있습니다.

## 안전·데이터
- 명령 라우팅과 프로젝트명 매칭은 Mac 내부에서 실행됩니다. 이전에 등록한 로컬 서버의 \`/api/projects\`를 루프백 주소로 읽을 수 있지만, 열기 명령 자체를 외부 LLM에 전달하지 않습니다.
- 제안 단계에서는 Finder·브라우저를 열지 않으며 OS 권한을 임의로 승인하지 않습니다. 외부 GitHub 웹 접속은 사용자가 최종 승인 후 브라우저를 열 때에만 발생합니다.
- 기존 v2.6의 프로젝트·폴더 재검증, 제안 만료, 승인 1회 제한을 유지합니다. DB 작업 상태를 자동으로 완료하거나 코드를 수정하지 않습니다.

## 검증 범위
- Mac Swift 빌드 및 실제 앱 패키징.
- Swift 순수 파서 테스트: 등록 프로젝트 매칭, GitHub/Finder 대상 구분, 프로젝트 미지정·이름 중복·파괴적 혼합 명령 차단, 일반 질문의 기존 경로 유지.
- macOS SwiftUI Work 탭 및 작업 이어하기 패널을 보이지 않는 창에서 구성하는 테스트.
- Python 계약 검사와 기존 자동 테스트.
- 사용자 마이크 권한, 실제 음성 전사 및 실제 Finder/브라우저 열기 버튼 사용 결과는 별도 실기기 확인이 필요합니다.
