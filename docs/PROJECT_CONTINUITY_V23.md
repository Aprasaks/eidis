# JARVIS v2.3 — 프로젝트 작업 기억 및 이어서 하기

## 사용 방법
1. JARVIS 앱의 **작업** 탭으로 이동합니다.
2. 프로젝트를 선택하면 SQLite에 직접 기록된 목표·작업 수·마지막 GitHub 확인·이어 할 일·막힌 작업을 표시합니다.
3. **내 작업 기록**에서 작업 이름(최대 200자)을 적고 **예정 작업 추가**를 클릭합니다. 서버가 저장 성공을 응답한 뒤에만 저장됐다고 알려 줍니다.
4. 각 작업의 **상태 변경** 메뉴에서 예정/진행/막힘/완료를 직접 선택합니다. 서버는 이전 상태와 새로운 상태를 프로젝트 변경 이력에 남깁니다.
5. 진행 작업을 먼저, 예정 작업을 나중에 최대 5개까지 **다음 이어 할 일**로 표시합니다. 막힌 작업은 별도 표시하며 완료 작업은 다음 할 일 목록에서 제외합니다.
6. **자비스** 탭에서 `DECHIVE.WIKI 다음 뭐해야 해?` 등으로 문의하면 저장된 작업을 조회하여 다음 단계와 막힌 작업을 알려 줍니다. 이 질의는 GitHub 및 AI API 호출을 하지 않습니다.

## 증거와 한계
- 모든 작업 상태는 사용자가 직접 기록하는 메모이며, 코드 배포·실행 완료 여부를 증명하지 않습니다.
- 로컬 작업 생성 및 상태 변경에는 별도 GitHub/외부 API 요청이 없습니다. **GitHub 상태 조회는 별도의 1회 승인 화면**을 유지합니다.
- 입력값이나 서버의 성공 응답이 없으면 저장 성공이라고 주장하지 않습니다. 타임아웃/실패 시 중복 방지를 위해 자동 재시도하지 않습니다.
- 작업 추가/상태 변경 이력은 로컬 SQLite에 저장됩니다. 자비스를 종료·재시작해도 기록이 유지됩니다. 기존 DB를 초기화하거나 마이그레이션하지 않았습니다.
- 다음 할 일 순서는 사용자 기록의 `doing → todo` 상태를 단순 정렬한 것입니다. AI 우선순위 판단이나 자동 실행은 아닙니다.
- 실제 Mac UI에서 클릭·입력·상태 변경이 보이는지는 사용자 실사용으로 확인해야 합니다.

## 검증
- 임시 SQLite DB로 독립 로컬 서버를 열어 작업 생성, 상태 변경, 저장 재조회, 변경 이력, 도구 실행 기록 없음까지 자동 검증.
- Swift 합성 프로젝트 JSON/작업 상태를 이용해 `doing → todo` 추천 순서, 막힘 분리, 완료 제외를 검사.
- Python/Swift 전체 테스트와 macOS 앱 빌드 및 코드 서명 검증 수행.
