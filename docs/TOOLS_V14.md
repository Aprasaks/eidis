# JARVIS v1.4 — 확인 가능한 도구 실행

## 실제 동작
사용자: 자비스, 내 GitHub 프로젝트 상태 확인해

1. 읽기 전용 GitHub 상태 확인 의도가 분명할 때만 실행합니다. 부정 명령은 제외합니다.
2. 로컬 SQLite에 저장된 프로젝트와 GitHub owner/repo를 확인합니다. 여러 프로젝트면 대상을 지정하도록 요청합니다.
3. 허용된 도구 github.public_verify의 read_external 권한을 검사합니다.
4. 외부 요청 전 tool_executions에 시작 기록을 남깁니다.
5. 공개 GitHub REST API에서 기본 브랜치 HEAD SHA와 해당 SHA에 일치하는 최근 Workflow를 읽습니다.
6. 결과의 저장소·SHA·Workflow 링크·상태 형식을 검증하고 project_checks에 따로 기록합니다.
7. 실제 확인한 SHA, Workflow 상태, 확인 시각을 답변에 표시하고 완료/배포를 추정하지 않습니다.
8. 실패는 별도의 실패 기록으로만 남기며, 프로젝트 작업 상태는 자동 변경하지 않습니다.

## 권한
- 허용: 등록된 공개 GitHub 저장소 읽기 전용 확인. 반드시 직접 요청.
- 차단: GitHub 쓰기/커밋/PR 병합/배포/삭제, 셸 명령, Mac 파일 자동 수정.
- 외부 AI 모델 응답만으로 도구를 실행하지 않음. 도구 선택은 현 단계에서 규칙 기반.
- 자동 정기 실행 없음. 한 서버 실행에서 GitHub 확인은 최대 8회, 자동 재시도 없음.

## 사용 순서
1. 작업 공간 > 프로젝트 > 프로젝트 추가에서 이름과 공개 GitHub owner/repo 등록.
2. 하단 입력창에서 '자비스, 내 GitHub 프로젝트 상태 확인해' 입력 또는 Mac 음성 입력.
3. 여러 프로젝트가 있다면 'eidis GitHub 상태 확인해'처럼 이름을 명시.
4. 화면에서 결과 확인. 조회 영수증은 GET /api/tools/history, 허용된 도구는 GET /api/tools 에서 확인.

## 범위와 검증
- 실행 기록에는 도구 이름·프로젝트 ID·허용 권한·상태·관측 SHA·시각만 저장. 대화 원문과 개인 작업 제목은 기록하지 않음.
- 사용자 기록의 완료 상태와 GitHub 증거는 서로 분리.
- 공개 저장소에서만 작동. 비공개 repo 인증은 아직 불가.
- Workflow 일부를 확인하더라도 실제 Mac 앱 동작, AWS 배포, 공개 사이트의 정상 작동은 증명하지 않음.
- 공급자 API를 실제 사용자 앱에서 호출한 경험은 아직 없고, CI는 모의 응답으로 검증.
- Python 권한·오류·모호성·감사 이력 테스트, macOS 컴파일 및 브라우저 회귀 테스트로 검증.
