# JARVIS v3.6 — Mac 앱 하나로 로컬 서버 실행

## 해결한 문제

기존 Mac JARVIS는 별도의 터미널에서 python3 app.py를 먼저 실행해야 저장된 프로젝트 및 작업 내용을 읽을 수 있었습니다. 이번에는 **JARVIS.app을 열었을 때** 자체 로컬 Python 서버를 확인하고, 없는 경우 앱 내부에 함께 패키징한 Python 코드를 한 번 시작합니다.

## 실제 동작

- 자비스 앱 실행 → 127.0.0.1:8765/api/diagnostics에 연결 확인
- 이 URL이 **자비스의 로컬 읽기 전용 진단 형식**으로 답하면 이미 실행된 서버를 재사용합니다. 기존 서버를 종료하지 않습니다.
- 응답이 없다면 앱 내부 Contents/Resources의 Python 서버를 선택한 로컬 Python 3 실행 파일로 시작합니다. Python 3가 Mac에 설치되어 있어야 합니다.
- Python 소스와 웹 UI만 앱 안에 넣습니다. 개인 DB, API 키, Git 폴더, .env 파일은 패키징하지 않습니다. 로컬 DB는 기존 ~/.jarvis-lab/memory.sqlite3 경로를 그대로 사용합니다.
- 앱이 시작한 서버만 앱 정상 종료 시 종료합니다. 외부에서 이미 켜져 있던 다른 서버를 종료하지 않습니다.
- 유료 외부 AI 활성화 환경변수와 API 키는 앱이 시작하는 Python 프로세스에 상속하지 않습니다. Mac 작업탭의 Apple 기기 내 AI는 별도이며 영향을 받지 않습니다.
- 작업 탭과 자비스 탭이 처음 열렸을 때 서버가 아직 시작 중이어도, 연결 완료 신호로 자동 새로 고침합니다.
- 오류 시에도 서버 중복 실행/타 프로세스 종료/자동 재시도를 하지 않습니다. 사용자가 자비스 탭의 '연결 확인'을 눌러 재확인할 수 있습니다.
- Mac 로그인 시 자동 실행(로그인 항목), OS 백그라운드 데몬, 원격 서버 노출은 추가하지 않습니다. **앱을 직접 실행해야만 시작**합니다.

## 한계와 확인 방법

- 이 기능은 로컬 서버의 **시작/연결** 편의성을 개선하며, 외부 AI 두뇌나 새로운 도구 권한을 추가하는 기능이 아닙니다.
- 매번 localhost 8765를 확인합니다. 그 포트를 다른 프로그램이 사용하면 강제 종료하지 않고 실패 이유를 표시합니다.
- 앱을 비정상 강제 종료한 경우 자식 프로세스가 잠시 남을 가능성은 있습니다. 정상 종료 시에만 자신이 시작한 프로세스 정리를 보장합니다.
- Mac에는 Python 3가 설치되어 있어야 하며, 지원되는 경로는 /opt/homebrew/bin/python3, /usr/local/bin/python3, /usr/bin/python3입니다.
- 성공 여부는 실제 앱 설치 뒤 기존 서버 사용과 서버 없는 상태에서 각각 1회 구동해 확인합니다.

## Mac에서 실제 검증한 결과 (2026-11-17)

- JARVIS.app 버전 **3.6.0 (빌드 36)**을 기존 앱과 동일한 번들 식별자로 업데이트 설치했습니다. 기존 앱은 별도 폴더에 백업했습니다.
- 설치 전 사용자 SQLite **백업/quick_check** 성공. 이후 프로젝트 2개·작업 25개(완료 14, 예정 11) **변경 없음**.
- 기존 서버 PID 13074가 있을 때 새 앱을 열어 **그 서버를 재사용**했고, 앱을 정상 종료해도 해당 서버를 종료하지 않았습니다.
- 기존 서버를 별도로 종료한 뒤 앱을 **단독 실행**하자 새로운 Python 서버가 JARVIS 앱의 자식 프로세스로 시작됐습니다. HTTP 200, 실제 서버 작업 디렉터리는 **JARVIS.app/Contents/Resources**였습니다.
- 앱을 정상 종료했더니 앱이 시작한 Python 서버만 종료됐고, 8765 포트가 비었습니다. 앱을 다시 열었을 때 서버가 자동으로 다시 연결됐습니다.
- 실행한 설치 앱의 코드 서명은 재확인 시에도 유효했으며, Python 바이트코드 캐시 파일이 추가되지 않았습니다.
- 기존 Python 테스트와 Swift 서버 정책/앱 빌드 검증 완료. GitHub CI 결과는 별도 확인 예정.
- 정상 종료 기준의 테스트입니다. 강제 종료·정전 또는 시스템 재부팅 시 완전한 자식 프로세스 정리를 보장한다고 주장하지 않습니다.

**Mac 현재 상태:** 설치된 JARVIS 3.6.0과 앱 관리 로컬 서버가 실행 중입니다. 로그인 시 자동 시작은 설정하지 않았습니다.
