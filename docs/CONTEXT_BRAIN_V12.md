# JARVIS Context Brain — v1.2

> **구현 범위:** 같은 실행 세션에서 대화 흐름을 이어가고, 사용자가 명시적으로 저장한 SQLite 기억을 검색하며, 대시보드·화면·디자인 명령을 기존 엔진으로 처리하는 첫 대화 계층. 완성형 자율 AI가 아닙니다.

## 기본 동작 (API 사용료 없음)

- 하단 입력창과 Mac 음성 입력은 이제 공통 `POST /api/chat`으로 전달됩니다.
- 간단한 명령은 기존 검증된 규칙 엔진에서 실행합니다.
- 알 수 없는 일반 질문은 **AI가 연결되지 않았다는 사실**을 알려주며, 실행 또는 답변을 지어내지 않습니다.
- "방금 내가 뭐라고 했지?" → 직전의 사용자 발화를 현재 대화 세션 메모리에서 찾아 답합니다.
- "우리가 무슨 이야기 중이었지?" → 이 대화의 직전 주제를 확인합니다.
- "기억해: 위키 배포가 우선" → 명시적인 노트를 SQLite에 저장합니다.
- "기억 검색: 배포" → **직접 저장한** 기억에서만 일치하는 항목을 찾습니다.
- "대화 초기화" → 현재 대화의 임시 기록만 비우고 **직접 저장한 노트는 그대로** 둡니다.
- "우리 프로젝트 상태 알려줘" → 실제 연결되지 않은 GitHub·Mac·AWS 상태를 **확인했다고 주장하지 않습니다**.

## 기억과 사생활

- 현재 대화의 사용자 문장과 자비스 응답은 **파이썬 프로세스의 RAM**에서만 유지합니다.
- 세션별 최근 최대 12개 발화 메시지(6쌍)와 동시에 최대 12개 세션으로 제한합니다. 서버를 끄거나 오래된 세션이 밀리면 사라집니다.
- **원문 대화는 SQLite, 파일, 브라우저 storage, 통합 터미널 활동 로그에 자동 저장하지 않습니다.**
- 사용자에게 명시적으로 요청받은 `기억해:` 내용만 SQLite에 남습니다. 로컬 DB는 암호화된 금고가 아니므로 비밀번호·API 키를 저장하지 않는 것이 좋습니다.
- 명령과 응답의 처리 종류는 SQLite 활동 기록의 메타데이터로 남습니다. 로컬 서버 종료/재시작 시 대화 맥락은 재설정됩니다.
- 브라우저에 보이는 답변은 대화 응답 영역에 표시하고, 실제 작업 종류/오류만 코너 터미널에 표시합니다.

## 유료 AI 연결은 선택 사항 (기본 OFF)

일반 질문을 생성형 AI 모델로 처리하려면 **다음 세 가지를 모두** 직접 설정해야 합니다.

- `OPENAI_API_KEY`: 별도로 발급받은 API 키 (ChatGPT 구독과 과금 분리).
- `JARVIS_BRAIN_MODEL`: 사용할 수 있는 API 모델 ID. 코드에 모델 이름을 고정하지 않습니다.
- `JARVIS_ENABLE_BRAIN_API=1`: 외부 질문 전송을 허용하는 서버 측 스위치.

위 설정이 모두 있는 경우에만 입력창 위에 **이번 질문 외부 AI 전송 동의** 체크박스가 표시됩니다. 체크하지 않으면 외부 모델을 호출하지 않습니다. 체크한 **해당 질문 한 번**에 한해 현재 세션의 최근 8개 대화 메시지 및 관련성이 있는 최대 3개의 직접 저장된 기억을 함께 전송할 수 있습니다.

- API는 Responses API에 `store:false`와 `max_output_tokens:650`을 보냅니다.
- 한 서버 실행 중 외부 AI 호출 시도 최대 **3회**, 자동 재시도 없음.
- AI 응답은 **읽기 전용 텍스트**입니다. 다른 앱 조작·파일 수정·메일 발송·배포 도구는 연결되지 않았습니다.
- 현재 유료 API 실호출은 하지 않았습니다. CI는 가짜(mock) 공급자 응답만 테스트합니다. 실제 모델 사용 가능 여부/요금은 사용자 계정별 확인이 필요합니다.
- 대화 내용은 원격 AI에서 처리될 수 있으므로 민감한 내용을 포함한 질문은 체크하지 마세요.

## 검증

`python3 -m unittest discover -s tests -v`로 세션 격리, 명시적 기억 저장, 검색, 삭제 없는 초기화, 외부 동의/요금 상한, 모의 공급자 호출을 검증합니다.

실제 Chromium 데스크톱·모바일 테스트에서는 **명령 입력 → 로컬 답변 → 직전 발화 회상 → 대화 초기화**, 코너 로그의 원문 비노출을 확인합니다. Mac 음성 인터페이스 코드는 GitHub macOS 빌드에서 컴파일 검증하며, 실제 기기의 음성 인식/권한은 아직 검증되지 않았습니다.

## 앞으로 필요한 기능

- 실제 LLM API 연결과 사용량 검증 (명시적 승인 뒤에만).
- 대화가 끊겨도 이어지는 **프로젝트 상태의 구조화된 기억** — 우선 사용자 확인·승인 기반으로 설계해야 함.
- 허용된 도구를 읽고 쓸 수 있는 tool registry, 사용자 승인/실행/재확인 기록.
- 화면 한 장 이해와 음성 질문을 동일한 맥락으로 잇는 기능. 자동 화면 모니터링은 별도 동의/권한 필요.
