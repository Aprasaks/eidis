# DECHIVE JARVIS — Conversation First 1.0 (2026-11-21)

## 목표
실제 Mac 사용자 제보에 따라 **말 종료 후 오랜 대기**, **브라우저가 대화를 가리는 문제**, **브라우저가 키보드 포커스를 가져가면 Space 음성이 중단되는 문제**를 수정한다. 추가 AI/API/이미지 생성 없이 기존 금빛 코어와 저장된 개인 정보·프로젝트를 유지한다.

## 실제로 확인된 원인
1. 기존 자동 발화 종료 대기 기본값 6.5초 (5.0~12초 제한). 과거 6.5초 기본값이 UserDefaults에 저장되면 항상 그대로 복원됐다. 또한 동일한 ASR 부분 문장이 반복 송출되어도 무음 타이머를 재설정하는 문제가 있었다.
2. 기존 `JarvisSummonedView`는 브라우저가 열릴 때 오른쪽 대화 패널을 숨기면서, 가운데 하단 입력창과 오른쪽 WebKit 브라우저를 별도로 겹쳐 배치했다.
3. 기존 NSApplication 키보드 모니터에서 `browser.isVisible != true` 조건으로 Space를 의도적으로 비활성화했다. WebKit 텍스트 입력과 마이크 Space의 포커스 구분도 없었다.

## 구현
- 기본 무음 자동 종료를 1.8초로 변경. `jarvis.dialogue.fastPauseV1`로 이전 기본값 6.5초를 1회만 마이그레이션하고, 이전에 6.5초 외의 개별 사용자 설정은 보존한다. 허용 범위 1.2~8.0초. 이미 받은 것과 내용이 동일한 부분 인식 결과는 기다림 타이머를 리셋하지 않음.
- 일반 전체화면과 왼쪽 고정 대화 패널 양쪽에 자동 종료 속도 메뉴 표시: **빠르게 1.8초 / 보통 2.8초 / 천천히 4.0초 / 수동 종료(Space)**. 현재 선택은 저장된다. 빠르게 말하다 쉬는 경우 인식이 일찍 끊길 수 있으므로 2.8초 또는 4.0초로 전환할 수 있다.
- 브라우저·보관함·일반 대시보드·라이브 대시보드(non-overview) 오픈 시, 왼쪽 약 30%에 대화 기록·실시간 받아쓰기·마이크 버튼·텍스트 입력·전송 버튼을 고정. 오른쪽 남은 영역은 해당 작업 패널에 할당한다. WKWebView와 텍스트 입력이 서로 겹치지 않는다. 긴 대화는 왼쪽 패널 안에서 독립 스크롤한다.
- 작업 모드에서 원본 금빛 AVPlayer HD 코어를 축소·원형 마스킹으로 배경 처리. 일반 코어 화면은 원본 크기 그대로 유지한다. 전체대시보드(overview)는 기존 단일 화면 구조를 유지하고 별도 음성 단축키를 적용한다.
- 작업 화면 전환 시 오래된 FocusState를 리셋하여 숨겨진 입력창 때문에 Space가 영구적으로 막히지 않게 한다. 작업 패널 위를 드래그해 전체화면이 다른 모니터로 이동하는 것도 방지한다.
- 기존 Space는 **글 입력 중이 아닐 때** 마이크 시작/종료·응답 끼어들기에 사용. 별도 **Option+Space**는 브라우저 포커스가 있는 동안에도 명시적으로 음성을 제어하는 단축키. Carbon RegisterEventHotKey는 오버레이가 보일 때만 등록하며, 닫을 때 해제한다. 로컬 NSApplication 키다운은 보조 경로로 유지한다. 반복 키다운은 무시하고 0.25초 내 중복 처리는 제한한다.
- 현재 웹페이지가 `input`·`textarea`·`select`·contenteditable 등에 입력 포커스를 두었을 경우 평범한 Space를 가로채지 않는다. WebKit에 주입하는 경량 focusin/focusout 코드가 **참/거짓 한 개만** WKScriptMessageHandler로 보내며, 키 입력 텍스트·쿠키·문서 본문을 전달하지 않는다. 이 브리지는 페이지 조작·Qwen 명령 실행 권한이 전혀 없다. 웹페이지가 이를 모방해도 음성 명령 자체를 실행할 수 없다.
- 기존 Qwen 모델·스트림 방식·ElevenLabs 음성·권한/비밀키·API 조회 주기·연구 기능은 손대지 않았다.

## 테스트 및 근거
- Python 기존 전체 회귀 268개 통과. 새 `tests/test_conversation_first_workspace_v1.py`로 무음 설정·좌우 배치·음성 키보드·focus-only 브리지 확인.
- Swift 디버그 앱 빌드 통과. `macos/tests/voice-focus/main.swift`로 입력 중 Space 보존/Option+Space 작동, 키 반복·추가 modifier 거부 테스트.
- Mac Carbon 직접 테스트에서 Option+Space 등록 상태 0 (`noErr`) 확인.
- `macos/tests/voice-focus/webkit-live.swift`: 실제 공개 Python 사이트 WKWebView를 별도 임시 브라우저에서 열고 검색창 focus/blur를 조작. 실제 focus 상태 전달 및 입력 중 일반 Space 미가로채기, 포커스 해제 후 일반 Space 마이크 적용 판단을 검증.
- 대화·브라우저 화면 통합은 Swift 빌드와 소스 계약으로 확인. **실제 사람 음성 입력으로 ASR 1.8초 타이밍/자막 지연/Qwen 후속 처리 시간은 미검증**; 결과를 과장하지 않는다.
- Qwen 응답 생성은 여전히 전체 응답 수신 후 표시하는 방식이다. 1.8초 단축은 **무음 인식 지연**만 개선하며 모델 추론 속도, TTS 지연은 별도 개선 대상이다.
- iframe 내부 편집 입력 포커스·OS에서 글로벌 단축키를 가로채는 서드파티 앱 등 극단 상황은 별도 검증 필요. OS가 Option+Space를 다른 기능으로 사용하는 경우 마이크 버튼을 사용할 수 있다.
