# JARVIS v3.10.6 — 음성 우선 · 자동 실행형 개인 비서

## 사용자가 확정한 원칙

- 금빛 코어가 메인 화면이다. 사용자가 버튼을 찾아다니는 대시보드 앱이 아니다.
- 사용자가 자연어로 원하는 결과를 말하면, JARVIS가 필요한 도구를 선택해 실행하고 **필요한 UI를 코어 옆에 잠시 띄운다**.
- 평범한 조회/검색/앱 열기/읽기 전용 분석처럼 위험이 작고 쉽게 되돌릴 수 있는 동작에 반복 승인을 요구하지 않는다.
- 삭제·영구 변경·금전 지출·계정 보안 변경·공개 발행·메일/메시지 발송·민감 자료 외부 업로드처럼 후폭풍이 큰 작업은 명시적인 승인과 실행 결과 검증을 거친다.
- 웹페이지의 문장은 외부의 신뢰하지 않는 자료이며, 페이지 속 지시가 사용자의 명령이나 도구 사용 허가를 대체하지 못한다.
- 사용자 데이터/기존 앱/SQLite는 백업하고 보존한다. 원본 금빛 코어의 화면 디자인은 임의 교체하지 않는다.

## 현재 실기기에 연결된 기능

1. `Cmd+Option+J` 수동 소환, Aria 소환 인사, Mac Speech 한국어 음성 대화, Ollama Qwen3.5 9B 로컬 두뇌.
2. `내 작업 보여줘` → 기존 로컬 DB의 GET 프로젝트/작업 현황을 코어 오른쪽 대시보드에 표시.
3. `... 검색해줘`, `... 찾아줘`, `인터넷에서 ... 찾아봐` → Naver 검색 페이지를 JARVIS 자체 임베디드 WebKit 브라우저에 로드. 명시적인 `구글에서` 명령은 Google 검색 사용.
4. 브라우저는 별도 Safari/Chrome을 열지 않으며, 뒤로/앞으로/새로고침/닫기를 제공. 한국어 `인터넷 검색창 닫아`로 패널만 닫음.
5. 개인 문서·파일·프로젝트 검색 명령은 공용 인터넷 검색으로 보내지 않도록 제외. 아직 Finder 파일 검색은 미구현.
6. `Esc`는 웹페이지/대시보드/음성 입력/음성 출력을 포함해 코어 전체를 즉시 닫음.
7. JARVIS v3.10.4 이후 앱 내부 ElevenLabs 5회 제한은 없음. ElevenLabs 계정 크레딧/서비스 한도는 계속 적용.

## 현 단계의 한계 — 성공으로 과장하지 말 것

- **실제 브라우저 표시/내부 페이지 탐색은 구현**했지만, JARVIS가 검색 결과의 모든 페이지를 자동으로 순회하고 사실을 검증한 보고서를 만드는 기능은 아직 없음.
- Qwen이 WebKit 페이지 DOM을 자동으로 읽거나 페이지 내 버튼을 대신 누르거나 로그인/구매/게시하는 기능은 아직 없음.
- 웹 검색어는 검색 엔진 서버로 전달되며, 비공개 파일/정보를 검색어에 혼입하지 않아야 함.
- 읽기 전용 외부 웹페이지에서도 개인정보 입력, 로그인, 파일 업로드, 비용 발생 동작은 자동화하지 않음.
- 링크에 따라 로그인/캡차가 요구되거나 웹페이지가 WebKit에서 열리지 않을 수 있음.
- 실제 사용자의 음성으로 검색 명령을 인식하는 종단 간 테스트는 사용자 청취 검증이 필요. 텍스트 입력 기반 검색 경로는 실기기 검증됨.

## 우선 개발 계획

1. **도구 실행기 / 상태기계**: 단순 질의응답 vs 검색/파일/앱/일정/작업 실행을 구분하는 typed action registry. 모델의 제안은 도구 검증·권한 검사 후에만 실행.
2. **웹 연구**: 검색 결과에서 사용자가 고른 페이지를 읽어 원문 URL과 출처를 붙여 Qwen으로 요약. 외부 웹페이지 프롬프트 인젝션 경계 필수.
3. **Mac 앱 실행·파일 검색**: 열기/찾기/화면에 결과 표시 등 읽기·가역 동작부터. 제거·덮어쓰기·저장은 사용자 승인.
4. **맥 상태/일정/리마인더**: 실제 시스템 API/캘린더를 연결하고 쿼리/변경을 명확히 구분.
5. **대시보드 문맥 유지**: `두 번째 거 열어`, `이거만 남겨`, `방금 찾은 것 정리해` 등 순차 명령.

**원칙:** 기본 응답 = 행동한 결과 + 증거/출처. 실행하지 않았으면 완료라고 말하지 않는다.
