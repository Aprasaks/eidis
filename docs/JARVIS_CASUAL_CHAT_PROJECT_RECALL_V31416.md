# JARVIS 일상 채팅의 프로젝트 기억·정정 개선 · 2026-11-24

## 실제 화면에서 확인된 문제
- “애기야~”라는 사용자 호출에 자비스가 호출어를 지적하고 불필요한 AI 정체성 설명을 했다.
- 사용자가 프로젝트 수를 여러 개에서 줄였다고 정정했는데도, 이전 응답의 오해를 반복했다.
- “지금 알고 있는 내 프로젝트들을 말해봐”에 로컬 프로젝트 DB 접근 권한이 없다고 답했다.
- 실제로는 같은 Mac 로컬 API `GET /api/projects`에 JARVIS eidis, DECHIVE.WIKI 두 건이 등록돼 있다. 이것이 오라버니의 전체 프로젝트 목록이라는 뜻은 아니다.

## 해결 방식
- 채팅 모드에서 “애기야~”, “자비스야” 같은 단순 호출어에 자연스럽게 인사하며 불필요한 정체성 설명을 하지 않는다.
- 사용자가 바로잡은 말은 모델의 이전 추측보다 우선하고, 정리 후 프로젝트 개수가 정확히 확정되지 않았다면 임의 수치를 만들지 않도록 규칙을 추가했다.
- 프로젝트에 관한 말이 나오면 `127.0.0.1:8765/api/projects` **읽기 전용 GET 요청**으로 실제 등록 목록을 조회할 수 있다.
- 프로젝트 전체 목록을 직접 묻는 질문에는 조회된 프로젝트 이름을 모델 생성 없이 반환한다. 조회 실패 시 접근 자체가 불가능하다고 단정하지 않고 현재 연결 실패라고 답한다.
- 프로젝트를 줄였다는 일상 발언에는 로컬 등록 목록이 전체 프로젝트를 대표하지 않는다는 제약을 Qwen에게 컨텍스트로 전달한다.
- Qwen이 활용하는 기존 사용자 프로필·승인된 기억·최근 채팅 메시지는 유지한다.

## 정확성·개인정보 경계
- 최신 설치 환경에서 확인한 로컬 DB 등록은 2개다: `JARVIS eidis`, `DECHIVE.WIKI`.
- 유일한 개인 프로젝트 원천을 이 API라고 주장하지 않는다. DB 밖 GitHub 프로젝트 및 대화에서 미등록된 프로젝트가 존재할 수 있다.
- 이 기능은 실제 DB를 **조회만** 하며, 프로젝트를 임의 생성·수정·삭제하지 않는다.
- 화면 상단에 표시되는 **대화 학습 꺼짐**은 별도 선택 설정이다. 켜기 전에는 일상 대화를 영구 기억 후보로 자동 축적하지 않는다.
- 프로젝트 조회의 성공은 Qwen 모델 자체의 추가 학습을 의미하지 않는다.

## 검증 및 인계
- `JarvisCasualProjectKnowledge.swift`를 직접 Swift로 컴파일·실행해 실제 로컬 DB 프로젝트 2건 조회 검증.
- 사용자 정정에 대한 실제 Qwen 재응답 테스트를 수행하고, 임의 숫자 추측을 줄이는 규칙 추가.
- Python 회귀 전체 **372개 통과**, Mac Swift 빌드·Apple 서명 검증 및 앱 버전 확인.
- Mac 앱 설치 후 현행 프로세스, DB 무결성 및 읽기 전용 API를 다시 확인한다.
- UI 상의 실제 클릭·채팅 응답 사용성은 별도로 사람이 검증할 필요가 있다.
