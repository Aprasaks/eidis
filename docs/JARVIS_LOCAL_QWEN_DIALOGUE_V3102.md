# JARVIS v3.10.2 · 로컬 Qwen3.5 대화 통합

## 실제 구현

- 전체 화면 기존 금빛 원본 1080p 영상 유지 (`JARVIS_FullHD_Loop.mp4`)
- 기존 수동 소환 Cmd+Option+J, 모니터 간 이동 기능 유지
- Aria 소환 인사 이후 마이크 권한이 이미 승인된 경우에만 듣기 시작. 최초 권한 승인 때는 명시적 마이크 버튼 또는 Space 사용
- 대화 중 Space로 음성 입력 시작/종료, 실제 on-device Korean SFSpeechRecognizer 사용 (서버 음성 인식 사용 금지)
- 사용자가 대화하는 동안 같은 세션의 최근 메시지만 메모리에서 유지
- AI 응답: `127.0.0.1:11434/api/chat`, `qwen3.5:9b-q4_K_M`, `think=false`, `stream=false`, 길이 제한, 한국어 응답 지침
- 대답: 기존 ElevenLabs Aria가 켜져 있으면 크레딧 사용 가능한 TTS, 기존 요청 한도 5회/실행 유지. 초과·오류 시 Mac 기본 음성으로 대체
- 동적 Qwen 답변을 코어 아래의 작은 창에 표시. 문자를 입력 중이면 Space를 빼앗지 않음
- 답변 읽기가 끝난 뒤 활성 음성 대화 상태인 경우 다음 질문을 다시 듣기
- Escape는 전체 화면에서만 Carbon 글로벌 핫키 등록, 다른 앱이 키보드 초점을 가져간 상태에서도 전체 화면/음성/대화를 취소함. 코어 닫으면 핫키 해제
- 외부 파일 읽기/수정/터미널 명령 등 LLM 도구 실행 기능은 제공하지 않음. Qwen 질문은 Mac 내부에만 전달하며, Aria TTS가 켜지면 답변 문장은 ElevenLabs로 전송됨

## 실제 맥 검증 (2026-11-20)

- Apple M4 Pro, 24 GB, Ollama 0.40.16 서비스 및 `qwen3.5:9b-q4_K_M` 확인
- Ollama POST `/api/chat` `think:false` 직접 테스트: HTTP 200 / 한국어 `2 입니다.` / 약 1.8초 (짧은 테스트 문장; 일반 응답 시간 보장 아님)
- v3.10.1 앱 전체 화면 하단 입력으로 `Hello Jarvis. Please answer in Korean.` 전송, 실제 코어 화면에 `안녕하세요! 저는 자비스입니다. 궁금한 점이 있으시면 언제든 물어봐 주세요.` 표시
- 입력창 FocusState와 Space 단축키 충돌 수정 확인: 공백을 포함한 입력 정상 저장·전송
- v3.10.2 코드 Swift 빌드·서명 검증, Python 자동 테스트 150개 통과
- v3.10.2 설치된 앱: 기본 창 숨김, Cmd+Option+J 전체 화면 확인
- macOS Accessibility 실제 마이크 버튼 클릭 후 `듣는 중` 상태 확인
- Finder 활성화 상태에서 Esc로 화면 사라짐 확인, 마이크 대화 시작 중에도 Esc로 화면 사라짐 확인
- Ollama `127.0.0.1:11434` 전용 TCP 바인딩 확인, 기존 프로젝트 수 2 확인
- 백업: `~/Applications/JARVIS-Backups/JARVIS-before-v3102-20261120.app`

## 사용자 확인이 필요한 부분

- 사람이 실제 한국어로 말한 내용이 정확히 인식되는지 (실기기 마이크로 말한 인식 결과는 별도 확인 필요)
- Aria 답변이 실제 스피커에서 자연스럽게 재생되는지 (UI/서비스 경로 확인과 청취 확인은 별개)
- 일부 Mac 권한/키체인 접근은 앱 서명 갱신 후 다시 승인해야 할 수 있음

## 현재 범위 밖

- `자비스` 단독 웨이크워드 없음 (수동 소환 유지)
- 실제 일정/업무/뉴스 데이터를 조회해 대시보드를 띄우는 명령형 기능은 아직 구현하지 않음. 지금은 질의응답 자막 패널만 제공
- LLM은 파일 변경이나 앱 제어를 할 권한이 없고, Qwen은 현재 사용자의 일정/프로젝트 내용을 자동으로 알고 있지 않음
- 영구 대화 기록/학습 없음. 종료 Esc 시 메모리 메시지 삭제
