# DEKA opt-in app integration — experimental
- Existing JARVIS name, visuals, API boards unchanged. Uses local .jarvis-lab/wakeword Python 3.10 venv and deka_ko_experimental.onnx; not bundled or distributed.
- Menu "데카 호출 실험 시작 (3분)" enables a single experimental wake attempt, uses small core, requires microphone permission. Off by default; no preference to persist arming. No launch agent/autostart.
- Native AVAudioEngine captures microphone only after local worker READY, converts to mono 16kHz signed PCM, nonblocking pipe to worker. No recording or network transfer of standby audio. Bounded startup 15s and listening 180s; stop on first hit, explicit stop, errors, mini hiding/fullscreen transition, manual voice, settings, sleep, app termination. Existing microphone callback stops wake capture before native recognition.
- On hit, release wake mic, local Mac TTS "네, 주인님.", then existing Korean on-device command capture. Say command after greeting. Existing answer behavior (including previously configured ElevenLabs and tools) unchanged. Re-arm from menu for a new wake attempt; no permanent background mode or speaker authentication.
- Candidate synthetic result 8/8 calls, 9/80 false; user live guided result 2/4 calls, 0/4 noncalls. Not certified reliable; no automatic rearming. Real end-to-end app microphone, voice playback and handoff still require user test.
- Unit smoke: worker protocol with one synthetic call, two noncalls and six seconds silence; Swift 48kHz float to 16kHz PCM conversion with generated sine, 2720 bytes, idempotent close. No microphone used in these automated checks.
