# DECHIVE Knowledge 본문 이미지 제작 규칙 v1.1

## 1. 공통 원칙
본문 이미지는 장식용 삽화가 아니라 글의 핵심 개념을 설명하는 교육용 도식이다.
reference/reference-body-01.png의 기존 편집 톤을 참고한다.
가로형 16:9, 기존 1672 × 941px 기준. 짙은 남색 바탕, 높은 대비, 읽을 수 있는 한글 라벨과 명확한 화살표를 사용한다.
한 이미지에서 설명할 핵심 개념과 독자가 이해해야 할 관계를 먼저 정한다. 주제에 필요하지 않은 상자, 화살표, 장식은 넣지 않는다.

## 2. 레이아웃과 한글 조판
- 배경 생성과 최종 한글 조판을 분리할 수 있다. 정확한 문구가 필요한 경우 Swift/AppKit 등 로컬 조판을 우선한다.
- 이미지의 바깥 안전 여백은 1672 × 941px 기준 최소 48px를 확보한다. 제목, 라벨, 주요 내용과 연결선이 잘리지 않게 한다.
- 모든 글자의 실제 렌더링 영역을 측정한다. 상자 내부 라벨은 테두리에서 최소 24px 떨어뜨리고, 외부 라벨도 테두리와 최소 24px의 간격을 둔다. 다른 해상도에서는 비례 적용한다.
- 글자와 테두리·화살표·사진·다른 글자가 겹치지 않게 한다. 상단과 하단 라벨은 반드시 각 경로에 명확히 귀속되어야 한다.
- 제목/단계명/보조 설명의 크기 차이를 유지한다. 공간이 부족하면 글씨부터 줄이지 말고 문구를 간결하게 하거나 상자와 여백을 재배치한다.
- 배경의 상자 위치를 추측하여 좌표를 고정하지 않는다. 실제 생성된 배경에서 경계를 확인한 뒤 조판하거나, 도식의 상자·선·라벨을 같은 좌표계에서 직접 그린다.
- 의미 없는 빈 상자나 단계 중복을 만들지 않는다. 데이터 자체와 데이터에 수행하는 동작(학습, 평가 등)은 명확히 구분한다.

## 3. 논리적 정확성
- 모든 입력과 출력의 관계, 단계의 순서, 분기, 변환 전후의 대응을 먼저 설계한다.
- 분할 도식에서는 모든 분기 결과가 원본 집합에서 유래해야 한다. 원본에 없는 항목이 분할 결과에서 갑자기 나타나면 불합격이다.
- 동일 항목의 변환 전후에는 사진, 식별자 또는 일관된 시각 단서를 유지한다. 독립된 항목은 다른 원본임을 명확히 표현한다.
- 화살표의 출발점과 도착점이 실제 의미와 일치해야 한다. 존재하지 않는 관계나 잘못된 인과 관계를 암시하지 않는다.
- 본문 이미지의 라벨과 의미는 원고, ALT, 캡션, 삽입 위치와 일치해야 한다.

## 4. 이번 K03-06 도식에만 적용하는 조건
- 먼저 원본 데이터 집합을 학습용과 평가용으로 분할한다.
- 원본 집합에 학습용 여우 사진 A·B·C와 독립 평가용 여우 사진 D를 모두 표시한다. D는 눈 덮인 배경 등으로 A·B·C와 명확히 구분한다.
- 학습 경로에는 원본 집합에 있던 A·B·C만 배치하고, 각각의 사진을 실제 회전·자르기·밝기 조절 등으로 변환한 결과를 보여준다.
- 학습 경로: 학습용 원본 → 증강 → 증강된 학습 데이터 → 모델 학습. 데이터와 모델 학습은 서로 다른 단계로 표시한다. 공간이 부족하면 증강 결과 상자에 '증강된 학습 데이터'를 표시하고 마지막 상자를 '모델 학습'으로 분리한다.
- 평가 경로에는 원본 집합에 있던 D만 표시하고 '독립 평가 데이터 (증강하지 않음)'으로 명시한다. 동일 원본이나 그 변형이 양쪽에 들어간 것처럼 보이지 않게 한다.
- 평가 경로는 모델 학습으로 들어가지 않는다. 평가용 입력의 일관된 전처리와 학습용 증강을 혼동시키지 않는다. '독립 평가' 단계는 학습이 끝난 모델의 성능을 확인한다는 의미로 표시한다. 필요하면 학습된 모델에서 평가 단계로 점선을 연결하되, 평가 데이터가 학습에 사용되는 것으로 오해되지 않게 한다.
- 한글 라벨은 최소 '원본 데이터', '학습용 원본', '증강', '모델 학습', '독립 평가 데이터'를 실제 이미지에 넣는다.
- 다른 주제에 K03-06의 여우 사진, 데이터 분할 방식, 문구를 그대로 재사용하지 않는다.

## 5. 최종 검수 및 실패 판정
완성 PNG 자체를 이미지 보기 도구로 실제로 열고 아래 항목을 확인한다. 원본 크기와 축소본(폭 800px 및 400px)을 모두 확인한다. 모바일 크기에서 주요 단계가 읽히지 않으면 문구와 배치를 조정한다.

- [ ] 모든 필수 한글 문구가 정확하며 잘리지 않았다.
- [ ] 글자와 테두리, 화살표, 사진, 다른 글자가 겹치지 않고 안전 여백을 지켰다.
- [ ] 모든 상자와 라벨에 의미가 있으며 잘못된 단계 배치나 불필요한 빈 상자가 없다.
- [ ] 분기·변환·입출력·항목 동일성 등 개념의 시각적 논리가 정확하다.
- [ ] 원고·ALT·캡션과 일치하며 축소 화면에서도 핵심 단계가 읽힌다.

report.md에는 항목별 실제 확인 결과와 발견된 결함, 수정 여부를 기록한다. 단순히 PNG가 존재하거나 보고서에 pass를 적었다고 검수가 끝난 것이 아니다. 하나라도 누락되거나 실제 시각 확인이 불가능하면 body-01.png explanatory check: fail 및 final package status: incomplete로 기록한다. 기존 최대 한 차례 수정·재검사 제한을 유지하며, 실패가 남으면 발행하지 않는다. AI 자체 검수와 독립 검증을 구분한다.
