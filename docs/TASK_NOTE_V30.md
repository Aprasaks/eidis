# JARVIS v3.0 — 승인 후 작업 실행 메모 저장

## 목적
자비스에서 작업 상태만 바꾸는 대신, 작업을 수행하기 위한 **기록용 Markdown 메모**를 Mac의 해당 프로젝트에 남깁니다. 실제 작업이나 코드를 자동 실행하는 기능이 아닙니다.

## 사용
1. JARVIS Mac 앱 **작업** 탭에서 프로젝트를 고릅니다.
2. **Mac 코드 상태**의 **Git 폴더 연결**에서 원하는 로컬 프로젝트 Git 폴더를 직접 선택합니다. 연결이 이미 되어 있다면 다시 선택할 필요는 없습니다.
3. **다음 할 일 시작**에서 예정·진행 작업 옆의 **실행 메모**를 클릭합니다.
4. 화면의 단계 초안을 필요에 맞게 수정합니다. 민감한 정보는 입력하지 않습니다.
5. **Markdown 저장 내용 미리보기**에서 프로젝트명, 작업 제목, 파일 경로와 전문을 확인합니다.
6. **메모 파일 저장 승인 화면 → 승인하고 새 메모 파일 저장**을 누르면 새 파일을 **한 번** 작성합니다.

저장 위치는 연결된 Git 루트 아래의 `.jarvis/notes/task-<작업번호>-<8자리 코드>.md`입니다. 매번 고유 이름을 만들며 같은 파일을 덮어쓰지 않습니다.

## 검증·보호
- **제안 만들기 / 미리보기**만으로 파일을 쓰지 않습니다.
- 승인 유효기간은 2분입니다. 파일을 쓰기 전에 루프백 프로젝트 API를 새로 조회하고 프로젝트 ID/이름/저장소, 작업 ID/제목/기록 상태, 연결된 로컬 폴더가 일치하는지 확인합니다.
- 연결된 Git 폴더는 실제 Git 루트로 직접 연결한 경로를 재사용합니다. 심볼릭 링크 우회를 차단하고 `.jarvis/notes` 경로만 허용합니다.
- 파일 쓰기 시 기존 파일 덮어쓰기를 방지하며, 저장 후 실제 내용을 승인한 미리보기와 비교합니다.
- 응답이 불확실하거나 저장 실패 시 다른 파일명이나 경로로 자동 재시도하지 않습니다.
- 현재 작업 상태·코드·Git 커밋·푸시·배포를 변경하지 않으며 브라우저/Finder도 자동으로 열지 않습니다.
- 이 파일은 **프로젝트 Git 폴더 안에 생성**되므로 사용자가 이후 Git에 추가하면 커밋 대상이 될 수 있습니다. 자동으로 `.gitignore`를 수정하지 않습니다.

## 검증 범위
Mac에서 별도 **임시 Git 테스트 폴더**를 생성해 Markdown 파일을 실제 작성하고 내용을 비교했습니다. 덮어쓰기·만료·프로젝트/폴더 변경·Git 루트 누락·심볼릭 링크 접근 차단 테스트도 통과했습니다. 실제 사용자 프로젝트 폴더로의 메모 저장이나 실제 Mac 버튼 클릭은 사용자 승인 전까지 수행하지 않았습니다.
