# DECHIVE 원격 API 갱신 간격 조정 · 2026-11-21

## 발견
- 전체 현황 화면이 열린 동안 약 7초마다 로컬 API를 갱신함.
- 기존 GitHub 계정 조회는 60초마다 가능하며 `gh api --paginate`로 페이지당 API 요청 1회 이상이 될 수 있음.
- Vercel은 120초마다 프로젝트 목록·배포 목록을 CLI로 각각 조회함.
- 기존 화면 `show()`가 GitHub/Vercel 조회 시각과 스냅샷을 초기화해, 대시보드에 다시 들어갈 때 바로 외부 조회를 재실행할 수 있었음.

## 이번 수정 범위
- GitHub 원격 확인: 최소 600초(10분) 간격.
- Vercel 원격 확인: 최소 900초(15분) 간격.
- 대시보드 같은 창을 닫고 다시 열 때 조회 시각과 마지막 결과를 유지.
- 전체화면 오버레이를 닫아 새 대화 객체가 생성돼도 같은 Mac 앱 프로세스 안에서는 RAM 캐시와 마지막 호출 시각을 유지.
- 데이터 화면에는 마지막 원격 확인 시각 및 분리된 주기를 표시. 빠른 7초 루프는 로컬 UI 확인에만 유지.
- 스캔 실패도 반복 호출 방지를 위해 시작 시각을 기준으로 쿨다운. 사용자가 OS에서 앱을 완전히 종료 후 재실행하면 이 RAM 캐시는 초기화됨.
- 외부 인증 정보, 로그인 상태, GitHub/Vercel CLI 자체, 다른 서비스의 갱신 주기, 데이터베이스 구조는 변경하지 않음.

## API 예산 의미
- 대시보드를 계속 열어둔 1시간 기준, 최대 GitHub 원격 검사 약 6회(페이지별 실제 요청은 별도), Vercel 검사 약 4회(각 검사당 CLI 목록 2회)로 축소.
- 정확한 API 잔여량은 서비스와 계정에 따라 변하고, 타 앱 요청도 공유할 수 있으므로 '절대 제한에 걸리지 않는다'고 보장하지 않음.
- GitHub REST 일반 인증 기준 기본 호출 제한 5,000회/시간; 비인증 60회/시간 (공식 GitHub REST 문서). Vercel 실제 제한은 응답 헤더/계정 및 엔드포인트 기준으로 확인 필요.

## 검증
- 기존 `tests/test_jarvis_command_center_v3140.py`에서 새 간격을 검증.
- `tests/test_dashboard_remote_api_throttle_v1.py`에서 7초 로컬 분리, 외부 주기, 캐시 초기화 방지 및 읽기 전용 검사 검증.
- 실제 Mac Swift 빌드와 Python 전체 회귀 검사, 앱 코드서명·패키지 검증 후 설치함.
- 이 변경은 동일 앱 프로세스 내 쿨다운이다. 앱 강제 종료/재실행을 반복하는 경우까지 영구적인 API 제한을 제공하지 않음.
