# JARVIS Learning Loop v1 · 2026-11-24

## 목적
실제 Mac JARVIS의 로컬 Qwen3.5 9B가 사용자가 직접 밝힌 **지속적인 선호, 대화 방식, 작업 원칙, 가치관, 목표, 프로젝트 결정**을 후보로 추출한다. 사용자가 승인한 후보만 다음 대화의 검색 컨텍스트로 보낸다. 모델 가중치의 추가 학습/미세조정은 수행하지 않는다.

## 실제 저장 위치 및 기존 데이터 보존
- Mac: `~/.jarvis-lab/memory.sqlite3`의 별도 `learning_settings`, `learned_memories`, `learned_memory_revisions` 테이블.
- 기존 `personal_profile`, `memories`, `vault_items`, `calendar_events`는 변경/초기화하지 않는다.
- 오디오, 모든 대화의 전체 원문, AI 답변을 자동으로 저장하지 않는다. **학습을 켠 상태에서** 추출 가능성이 높은 발언 중 짧은 원문 발췌(최대 500자)와 후보(최대 140자)를 저장한다.
- 비밀번호·토큰·연락처 등을 기본적인 패턴으로 차단한다. 자동 감지가 완전하다고 가정하지 않는다. 민감한 대화에서는 학습을 꺼야 한다.
- 클라우드 API에 저장하지 않는다. Ollama `qwen3.5:9b-q4_K_M`가 로컬에서 추출한다. iPhone 동기화는 아직 미구현.

## 사용자 사용 방법
- Mac JARVIS 실행, **“전체 대시보드 열어”** → `KNOWLEDGE / 자료·기억` 카드에서 **학습 켜기**.
- 또는 음성/입력으로 **“자비스, 학습 켜줘”**.
- 그 뒤 평소처럼 대화한다. 예: **“나는 블로그 글을 작성할 때 공식 출처를 먼저 확인하고 싶어.”**
- 답변 이후 Qwen이 후보를 제안하면 카드에서 승인/거절한다. 후보는 **승인 전** Qwen 답변에 사용되지 않는다.
- 음성/입력 명령: **“기억 후보 보여줘”**, **“기억 후보 1번 승인”**, **“기억 1번 거절”**, **“기억 1번 수정: 결론부터 간결하게 말해줘”**, **“기억 1번 삭제”**, **“학습 꺼줘”**.
- 학습을 끄면 새 후보를 추출하지 않는다. 이미 승인된 기억은 사용되며, 개별 삭제할 수 있다.

## 기술 흐름
1. 확정된 사용자 입력으로 정상 답변을 제공한다. 진행 중 답변과 음성 기능을 방해하지 않는다.
2. 옵트인 상태에서 지속적인 사용자 직접 발언이 감지되면 **답변 이후** 보조 Task가 로컬 Qwen에 JSON 스키마로 후보를 요청한다.
3. 후보는 `pending / ai_extracted_pending`으로만 기록된다. 중복 후보는 SHA-256 지문으로 중복 삽입을 방지한다.
4. 사용자가 직접 승인하면 `approved / user_approved`가 되고, 관련 사용자 질문 및 대화 방식에서 검색된다.
5. 변경 시 수정 이력을 남기고 현재 내용만 검색하며, 삭제 시 기억과 수정 이력을 실제 삭제한다.
6. 새로운 질문·작업 중단 시 백그라운드 추출을 취소한다. 로컬 Qwen 공유 모델 게이트와 저전력/과열 제한을 적용한다.
7. 추가 학습(Fine-tuning)은 향후 평가할 별도 기능이다. 매일 Qwen 모델 가중치를 갱신하는 기능은 아니다.

## 검증
- API/SQLite: 사용자의 선택에 따른 활성화, 후보·승인·거절·수정·삭제, 기존 데이터 유지, 프로세스 재시작 후 기억 재검색, 비밀정보 차단.
- Mac Swift 빌드 및 기존 전체 Python 회귀 테스트.
- 로컬 Qwen 샘플 추출(별도 테스트 문장)은 실제로 호출해 분류와 문장 길이를 확인.
- 실제 Mac 앱 **v3.14.14 / build 88** 서명 후 설치 및 실행 확인. 127.0.0.1:8765의 새 `/api/learning` 응답과 기존 프로필·자료·일정 수, SQLite 무결성 검사 확인.
- 사용자 DB는 설치 전에 SQLite 온라인 백업을 생성해 무결성을 확인함: `~/Library/Application Support/JARVIS/Backups/memory-before-learning-v31414-20261124.sqlite3`.
- 설치된 앱의 실제 API에서 임시 기억 후보 → 승인 → Qwen 검색 컨텍스트 → 수정 → 완전 삭제 검증. 테스트 기록은 삭제했고 학습 활성화 여부는 초기 **꺼짐** 상태로 복구함.
- 현재 마이크를 사용한 음성 명령의 기기 실사용과 대시보드 버튼의 직접 클릭은 아직 사용자 측 별도 확인이 필요함.
- iPhone 학습 기억 동기화와 자동 LoRA 학습은 **포함되지 않음**.

**실사용 원칙:** 데이터 축적의 양보다, 승인한 기록이 정확하게 다시 쓰이고 잘못된 기록을 정정하는지가 중요하다.
