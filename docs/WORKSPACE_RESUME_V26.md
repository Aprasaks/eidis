# JARVIS v2.6 — 승인 기반 프로젝트 작업 공간 열기

## 사용 순서
1. Mac 앱 **JARVIS → 작업**에서 프로젝트를 선택합니다.
2. **작업 이어하기 · 승인 후 Finder / GitHub 열기** 섹션에서 원하는 대상을 체크합니다.
   - **Mac 프로젝트 폴더를 Finder에서 열기**: 먼저 같은 프로젝트의 **Git 폴더 연결**에서 직접 선택한 로컬 저장소가 있어야 합니다.
   - **GitHub 저장소를 브라우저에서 열기**: 해당 프로젝트에 저장된 정확한 `owner/repo` 경로를 사용합니다.
3. **작업 이어하기 제안 만들기**를 눌러 실제 열기 대상과 주의사항을 확인합니다.
4. **열기 작업 1회 승인 화면** → **승인하고 선택한 작업 공간 1회 열기**를 눌러야 실행됩니다. 취소하면 아무것도 열지 않습니다.
5. 화면에 각 열기 요청의 수락/실패를 구분해서 표시합니다.

## 실행 범위와 검증
- 외부 앱 실행은 오직 마지막 승인 버튼에서 `NSWorkspace.shared.open(URL)`으로 요청합니다.
- Finder는 이미 사용자가 연결한 실제 로컬 Git 루트만 열 수 있습니다. 폴더 연결 변경, 경로 이동, 심볼릭 링크 리디렉션, `.git` 부재는 차단합니다.
- 브라우저 대상은 `https://github.com/{owner}/{repo}` 형태만 허용합니다. 프로토콜, 호스트, 하위 경로, URL 쿼리/프래그먼트 주입을 거부합니다.
- 프로젝트 ID·이름·저장소 경로는 승인한 제안과 실행 시점에 일치해야 합니다. 승인을 위해 만든 제안이 2분 이상 지나도 차단합니다.
- 새 제안을 만들거나 프로젝트를 선택하는 행위로는 아무 앱도 열지 않습니다. 각각의 승인 요청은 단 한 번만 실행합니다.
- Finder/브라우저 요청이 OS에 의해 수락되더라도 실제 폴더 창 표시, GitHub 페이지 로딩 성공, 로그인 여부까지 확인한 것은 아닙니다.
- 브라우저로 GitHub를 열면 사용자가 승인한 공개 페이지에 접속하며, 일반적인 브라우저 네트워크 요청이 발생합니다. 자비스가 로컬 코드나 파일을 업로드하지 않습니다.
- 파일 쓰기, 커밋, 푸시, 브랜치 변경, 배포, 삭제, 키보드 입력, 임의 웹사이트 이동은 지원하지 않습니다.

## 개인정보
- Mac 폴더의 절대 경로는 사용자 본인의 Mac 앱 UI와 설정에만 나타납니다. GitHub URL의 저장소 경로만 브라우저로 전달합니다.
- 작업을 열었다는 결과는 Mac 앱 메모리에만 남습니다. 새로운 DB/외부 기록 전송은 없습니다.

## 검증
- Swift 순수 함수 테스트에 가짜 `opener`를 주입하여 허용 경로, 악성 URL, 대상 변경, 제안 만료, 삭제된 Git 루트, OS 거절 결과를 검증했습니다. 테스트에서 Finder/브라우저는 열지 않았습니다.
- SwiftUI macOS 빌드와 Python 계약 테스트를 실행합니다.
- 실제 Mac에서 사용자가 체크박스·승인 창을 눌러 Finder/브라우저가 열리는지는 별도 실사용 검증 대상입니다.
