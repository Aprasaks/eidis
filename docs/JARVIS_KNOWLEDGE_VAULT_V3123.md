# JARVIS v3.12.3 — 데카이브 호칭 + 구조화된 자료 보관함

## 범위

- 사용자 호칭 `데카이브`: Mac 프로필 `personal_profile.display_name` 실제 변경, Qwen 한국어 호칭 규칙과 ElevenLabs 소환 인사 반영, 응답 TTS에서 브랜드 영문 `DECHIVE`를 `데카이브`로 발음. 모델이 사용자/자비스의 일인칭을 혼동할 때를 방지하기 위해 호칭 확인은 프로필 DB를 직접 조회함.
- 앱 기본 화면은 기존 금빛 코어. 사용자가 말로 저장·검색을 요청할 때만 오른쪽 **JARVIS · 보관함** 패널 열림. 프로필/프로젝트 대시보드와 별도로 유지.
- 로컬 SQLite `~/.jarvis-lab/memory.sqlite3`에 `vault_items` 테이블 추가. 기존 프로젝트 2개/작업 25개/프로필 8개 보존. 이전 대화나 파일을 무단으로 자동 수집하지 않음.
- 분류: `ideas` 아이디어 / `research` 조사·분석 / `projects` 프로젝트 / `references` 참고자료 / `notes` 일반 메모 / `tasks` 할 일 메모 (기존 작업 원장에 자동 등록되지 않는 메모).
- 메타데이터: 고유 ID, 제목, 본문(최대 8,000자), 분류, 관련 프로젝트, 태그, 사용자가 직접 준 글인지 현재 열린 HTTPS 웹페이지 원문인지 AI 답변인지, 출처 URL, 생성/수정 시각, 보관 상태. 웹 출처·AI 응답은 **검증 전** 표시.
- 분류 및 태그는 현재 **규칙 기반**. Qwen이 임의로 사실·태그를 만들어 넣지 않으며, 사용자 입력 본문은 원문대로 저장. 검색은 제목·본문·태그·프로젝트의 문자열 일치를 사용 (아직 의미 검색/임베딩 미연결).
- 자연어 명령: `블로그 아이디어: ... 저장해줘`, `지금 보는 페이지 저장해줘`, `이거 저장해줘` (열린 웹페이지가 있으면 페이지, 없으면 직전 AI 답변), `저장한 블로그 아이디어 보여줘`, `저장한 프로젝트 메모 보여줘`, `저장한 12번 자료 보여줘`, `12번 자료 삭제해줘` (복원 가능한 보관 처리), `12번 자료 복원해줘`, `보관함 닫아줘`.
- 구체적 내용이나 열린 페이지/직전 답변이 없으면 저장 대상 확인을 요청하고 임의의 기억을 생성하지 않음.
- 동일 본문+출처는 SHA-256 중복 확인으로 이중 저장을 막음. 저장 결과는 실제 DB 응답과 ID로 검증. 자료 삭제는 원본 삭제가 아닌 archive/restore.
- 외부 검색엔진 또는 외부 AI API로 로컬 보관함을 보내지 않음. 다만 사용자가 Aria TTS로 말하게 하면 출력 문장이 ElevenLabs로 전송될 수 있음.

## 실제 Mac 검증 · 2026-11-20

- 기존 DB는 별도 SQLite backup API로 복사: `~/.jarvis-lab/memory-backup-before-v3120-20261120.sqlite3` (`chmod 600`, quick_check OK).
- 기존 앱은 별도 보관: `~/Applications/JARVIS-Backups/JARVIS-before-v3120-20261120.app` 외 버전별 원본. 사용자 데이터 삭제/초기화 없음.
- v3.12.1 실기기에서 모델 DTO의 `sourceURL` 필드 디코딩이 `source_url → sourceUrl`로 바뀌는 오류를 발견: DB 저장은 성공했지만 UI는 저장 실패라고 표시. 이를 수정하고 실제 SQLite JSON을 Swift 디코더로 재검증.
- v3.12.2에서 보관함/검색 단어가 **저장할 본문에 포함된 경우** 명령이 검색으로 오분류되는 오류 확인 후, 명시적 `저장해` 동작을 먼저 파싱하게 수정.
- 실기기 `데카이브 블로그 아이디어: ... 저장해줘` → 아이디어/DECHIVE/#1 저장 및 UI 중복 방지 확인.
- 실기기 `자비스 개발 로그: 자료 보관함 검색을 검증하는 프로젝트 메모 저장해줘` → 프로젝트/JARVIS/#2 분류 및 실 UI에 저장 확인.
- 실기기 `저장한 자비스 프로젝트 메모 보여줘` → 프로젝트 한 건만 선별 표시. 2560x1080 외장 디스플레이에서 중앙 금빛 코어와 우측 보관함 배치 스크린샷 확인.
- 앱 및 내부 Python 서버를 완전히 종료·재실행 후 ID 1,2/분류/본문 보존 확인.
- 실기기 `나를 뭐라고 불러야 해?`: Qwen이 한 차례 `저를 데카이브라고 부르면 됩니다`라고 주어를 잘못 표현해, 질문을 직접 프로필 조회로 수정. 최종 v3.12.3에서 실제로 `데카이브라고 부르겠습니다.` 출력 확인.
- 테스트 용도로 만든 #1, #2 항목은 원본을 파괴하지 않는 archive로 정리: 현재 활성 보관함 **0건**, 두 항목은 복원 가능. 기존 프로젝트 2개/작업 25개/프로필 8건 유지, SQLite quick_check OK.
- Python 회귀 테스트 179개 + Swift 자연어 보관함 의도 14개, 사용자 프로필 의도 10개 통과, Swift 앱 빌드 및 안정적인 Apple Development 코드 서명 통과. 앱 재실행 후 키체인 허용 팝업 없음.

## 현재 지원하지 않는 기능

- 컴퓨터 임의 파일/사진/동영상을 자동 수집하거나 파일로 저장하는 기능은 아직 없음. 현재는 사용자가 명시한 텍스트·현재 JARVIS 내부 브라우저에 열린 읽기 가능한 HTTPS 페이지·직전 자비스 답변만 지원.
- Obsidian/Notion, Gmail, GitHub 파일을 직접 읽어 자동 저장하거나 동기화하는 기능도 아직 연결되지 않음.
- 저장 자료의 의미 기반 벡터 검색, 중복 의미 분석, 자동 전문 요약, 대화 전체 자동 저장은 아직 없음.
- 신규 저장 명령에 대한 실제 한국어 마이크 음성 인식은 사용자 직접 검증 필요. Mac 텍스트 입력과 앱 내부 데이터 저장·조회는 실기기에서 확인함.
