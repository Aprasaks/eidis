# DECHIVE RESEARCH ENGINE 1.1 — 근거 연결 및 출처 간 비교

작업일: 2026-11-21 / Mac 로컬 자비스

## 역할
1.0은 검색 결과와 원문 발췌를 저장한다. 1.1은 그중 실제 수집된 원문을 **추가 외부 조회 없이** 로컬 Qwen3.5에 전달해 주장의 후보·원문 인용·상이한 출처의 비교 가능성·반론·추가 검증 질문을 생성한다.

**중요:** 1.1이 확정하는 것은 *Qwen이 지목한 인용문이 해당 번호의 저장 원문에 실제로 존재한다*는 기술적 사실뿐이다. 인용된 주장 자체의 진실성, 출처의 실제 게시자 신원, 공식 출처 여부, 독립성, 주장 간 논리적 충돌 여부까지 확정하지 않는다.

## 구현
- 기존 research_jobs/research_sources를 읽기만 하고 `research_verifications`와 `research_verification_runs` 테이블만 추가.
- 완료 또는 부분 완료된 기존 조사에서 실제 읽은 원문(`retrieved`) 최대 4건만 스냅샷으로 만든다. 검색 색인만 확인한 `indexed_only`·원문 `unavailable`·안전 `blocked`는 검증 인용 근거로 허용하지 않는다.
- 사용자가 명시적으로 `자비스, 조사 1번 검증해줘`라고 요청했을 때만 대기열 등록. 원문 스냅샷 SHA-256으로 중복 작업 방지.
- Mac 로컬 Qwen `qwen3.5:9b-q4_K_M`: Ollama `/api/chat`, `think:false`, `stream:false`, `format:json`. 최대 주장 3건, 주장별 인용 3건, 발췌 원문 최대 1650자/원문, 생성 토큰 최대 1050. 원문은 인용 데이터로만 취급하고 Qwen에 외부 URL 접속·코드 실행·게시 권한을 주지 않는다.
- 모델 응답에 나오는 각 `rank`, `quote`, `stance`를 Python 코드가 검증. **인용은 지정된 원문에 글자 그대로 존재해야만 보고서에 들어갈 수 있다.** 다른 번호에만 존재하는 문장이나 허위 인용은 버리고 거부 건수를 기록한다. 인용이 전부 거부되면 `insufficient`로 표시하고 사실 판단을 보류한다.
- `supports/opposes/context`는 모델의 후보 분류이며, 서로 다른 출처에 상반된 표기가 있으면 `possible_conflict_requires_review`로만 기록한다. 서로 다른 도메인의 동일한 입장은 `multiple_domains_independence_unverified`이고, 독립적인 사실 확인이라고 부르지 않는다. 동일 도메인은 별도 검증 근거로 중복 계산하지 않는다.
- 출처별 URL·도메인·원문 수집 상태·실제 조회 시각·출처가 주장한 발행일을 제공. 발행일 형식 검토/미래 날짜 징후를 표시하지만 독립된 시간 검증은 아님. 게시자 신원은 `독립 확인 안 됨`으로 둔다.
- AI의 일반 해석은 `AI 해석 — 검증 전 가설` 섹션에 분리. 확인되지 않은 주장이나 임의로 고른 인용을 개인 기억 또는 확정된 사실로 승격하지 않는다.
- 대화 화면에서 `VERIFICATION / 인용 원문 대조` 표시: 실제 저장된 검증 번호, 대상 조사 번호, 상태, 후보 주장 일부와 원문 번호만 노출. 전체 보고서는 음성 `검증 보고서 N번 보여줘`로 불러온다.
- 백그라운드 검증은 앱이 살아 있고 전체화면 대화가 닫혀 있을 때만 실행. 음성 대화를 호출하면 검증 요청을 취소하며, 기존 STUDY CORE와 **한 번에 하나의 로컬 모델 작업만 실행**하도록 동일 잠금 장치를 사용한다.
- 24시간 최대 3회 모델 검증 시작, 동시 검증 1건, 작업당 최대 2회 시도, 작업 임대 180초. 앱/서버 중단 때 미완료 작업은 동일 근거와 실행 한도 안에서 재시도 가능. 기존 결과·실패 상태는 남는다.
- 로컬 `127.0.0.1:8765`만 바인딩하고 기존 Host/Origin 검사를 재사용. 서로 다른 로컬 프로세스 사이의 인증 경계는 추가하지 않았으므로 별도 보안 격리 제품은 아님.
- 새 API: `GET /api/research/verification/status`, `GET /api/research/verification?id=N`, `POST /api/research/verification/submit`, `.../claim`, `.../finish`, `.../cancel`.
- 실제 클릭/입력/브라우저 제어, 새 자료 자동 추적, 모델이 스스로 추가 웹 검색, 외부 게시/결제/삭제는 범위 밖.

## 검증된 실제 결과
- 원문 A "Python is a programming language that lets you work quickly and integrate systems more effectively." / 원문 B "Python is an interpreted, object-oriented, high-level programming language with dynamic semantics."를 **개인 DB와 분리된 임시 DB**에 저장.
- 실제 로컬 Qwen 연결·JSON 추론 후 정확한 출처 번호 두 건과 일치하는 인용을 받아 `draft` 기록 생성. 원문·인용 연결, 검증 보고서·재시작 후 복원을 확인.
- 처음 진단 중 Qwen이 B 문장을 A의 출처 번호로 잘못 분류한 사례가 실제로 발견됨. Python validator가 그 오류를 거부하도록 테스트 작성.
- 틀린 출처 번호, 허구 인용, 빈 결과, 동일 도메인 중복, 잠재적 충돌, 미래로 표시된 발행일, 사용자 중단과 늦게 도착한 결과, 임대 만료/재시도 제한, 외부 Origin 요청 거부를 테스트.
- Mac 코드가 실제 마이크를 통해 명령을 인식하는지, 장시간 시스템 부하 중 대화 우선순위가 실제 성능으로 유지되는지는 **미검증**이며 추후 현장 확인이 필요하다.
- Python 전체 회귀 264개 통과, Swift 명령 파서와 공유 모델 게이트 스모크 통과, Debug Swift 빌드 통과.

## 사용법
1. `자비스, DECHIVE 홍보 플랫폼 조사해줘.` (조사 1.0)
2. `자비스, 조사 현황 알려줘.` (실제 조사 번호 확인)
3. 조사 종료 뒤 `자비스, 조사 N번 검증해줘.`
4. 대화 화면을 닫으면 Qwen의 제한된 백그라운드 검토가 시작될 수 있다.
5. `자비스, 검증 현황 알려줘.`
6. `자비스, 검증 보고서 N번 보여줘.` (실제 검증 번호 확인)
