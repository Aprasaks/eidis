# JARVIS — 명시적 1회 새로고침 실행 v2.1

## 목적
JARVIS에서 사용자가 선택한 macOS 앱의 UI 구조를 수동으로 읽고, 그 중 **새로고침(Refresh/Reload)** 버튼이 정확히 1개인 경우에만 **사용자 승인 후 AXPress를 한 번** 수행하는 초기 조작 실험.

## 실제 사용
1. JARVIS 앱의 **UI 구조** 탭에서 대상 앱을 선택.
2. 접근성 권한이 필요하면 **접근성 권한 요청**을 클릭하고 macOS 설정에서 JARVIS 허용.
3. **화면 구조 읽기**를 클릭하여 선택한 앱의 UI를 수동 조회.
4. 대상 앱에 정확한 이름의 새로고침 버튼이 하나만 확인되면 **1회 실행 승인 화면**이 나타남.
5. 마지막 확인 창에서 **지금 새로고침 1회 실행**을 명시적으로 선택해야 API가 AXPress 한 번을 요청함. 취소는 아무 동작도 하지 않음.

## 동작 제한
- **허용 목록**: AXButton 역할이며 정확한 제목이 `새로고침`, `새로 고침`, `페이지 새로고침`, `Refresh`, `Reload`, `Reload this page` 등 지정된 항목일 때만.
- 절대로 실행하지 않는 기능: 임의 클릭, 입력, 이메일/메시지 전송, 삭제, 저장, 결제, 게시, 배포, 브라우저 자동화, 반복 클릭.
- 접근성 승인·대상 앱 및 창 상태·버튼 역할과 제목·활성화 상태·AXPress 지원을 조작 직전에 확인.
- 동일한 버튼 후보가 여러 개거나, 60초 이상 된 UI 조회, 앱/창/버튼이 달라진 경우 조작 금지.
- 한 번 시도하면 UI 조회와 버튼 참조가 무효화되며 재시도하지 않음.
- 앱에서 접근성 API가 성공했다고 알려도 실제 화면 변화나 페이지 갱신 성공을 보장하지 않음.
- 사용자에게 권한을 자동 승인하거나 비밀번호, 폼 값, 문서 본문 등을 읽지 않음.
- 선택 UI 참조는 메모리에만 저장. 외부 서버 및 데이터베이스에 기록하지 않음.

## 주의
**새로고침도 미저장 입력 내용이 사라질 수 있습니다.** 저장하지 않은 작업이 있는 화면에서는 사용하지 마세요. 기존 노출된 UI 접근성 구조를 읽는 기능과 로컬 OCR은 이 새로고침 API와 분리되어 있습니다.

## 검증
- Swift 패키지 및 macOS 앱 빌드.
- Python 단위 테스트.
- Swift 순수 정책 테스트: 정확한 새로고침 이름만 허용, 저장·삭제·전송·결제·메뉴·텍스트필드는 거부.
- **실제 macOS 접근성 승인과 다른 앱의 AXPress 성공 여부는 미검증**. 승인 없는 실기기 클릭은 시험하지 않음.
